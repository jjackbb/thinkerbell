# UX/UI 우선순위 초안과 사용자 결정

작성: 2026-09-22 · 목적: 사용자가 직접 UX/UI를 개선할 때 **무엇부터, 왜, 어디까지** 할지 판단하는 자료.

현재 화면을 다시 그리거나 실제 코드를 변경한 결과가 아니다. 아래 문구·배치·상태는 모두 **검토 후보**이며, 사용자 확정 사항만 별도 표시한다.

## 1. 확정한 것

| ID | 사용자 결정 | 적용 |
|---|---|---|
| D01 | 첫 사용 흐름과 AI 도움 여부부터 확인 | 재방문·결제보다 첫 핵심 과업과 도움 평가가 우선 |
| D02 | GA4는 아직 연결하지 않음 | UX 수정 전 GA4 수치를 과거 성과로 만들지 않음 |
| D03 | UX/UI는 사용자가 직접 할 예정, 팀원 수정안은 없음 | 작업자는 근거·우선순위·시안 후보를 준비하고 사용자와 결정 |
| D04 | 기존 사연→AI의 가시성·모드 설명부터 개선 | 비공개 AI 단독 진입 신규 기능은 첫 범위에 추가하지 않음 |
| D05 | 알림·구독은 준비 중임을 명확히 표시 | 실제 알림 전달·구매를 이번에 구현하는 것으로 확대하지 않음 |
| D06 | 나에게만 숨기기와 작성자의 전체 비공개를 모두 제공 | 버튼·저장·권한·취소/복원·이벤트를 각각 분리 |
| D07 | 확인이 필요한 부분은 임의 처리하지 말고 질문 | UI·정책·측정의 미결정은 아래 목록에서 관리 |
| D08 | 비공개 사연의 댓글·투표 보관, 재공개 시 복원 | 비공개 동안 타인의 접근·참여 차단. 비공개/재공개를 삭제/재생성으로 구현하지 않음 |
| D09 | 기존 AI 대화 보존·이용 허용, 해당 사연의 새 대화 생성만 차단 | 기존 대화 소유자의 열기·이어하기 허용, 생성 시 공개 상태 별도 검사 |
| D10 | 종료 시 선택 평가 1문항 저장 + 짧은 인터뷰 | 평가 내용은 GA4 전송 제외. 문구·선택지·보관 세부는 후속 검토 |

기존 승인 내용을 반복 질문하지 않는다. 이번 의뢰의 실행 범위는 분석·설계이며, 실제 앱 구현은 별도 요청 때 시작한다.

## 2. 우선순위 판단 기준

우선순위는 표본 2명의 빈도를 점수로 부풀린 결과가 아니다. **첫 과업을 막는가 → 결과를 잃거나 잘못 믿게 만드는가 → 서비스 가치와 연결되는가 → 현재도 남아 있는가**를 기준으로 한 작업자 제안이다.

P0 기능 오류는 디자인 확정과 병행해 재현·수정 준비한다. UX/UI는 U01→U04를 먼저 한 묶음으로 보고 U05 이후를 이어간다. 아래 순서는 추천이며 첫 상세 시안에서 사용자가 조정할 수 있다.

| 순서 / ID | 사용자가 겪는 문제 | 수정 후보 | 지금 먼저인 이유 | 완료 확인 |
|---|---|---|---|---|
| 1 / U01 | 로그인/둘러보기 후 지금 어디이며 무엇을 할지 불명확 | 현재 탭 강조, 홈의 첫 행동 정리, 로그인 상태 표시 일관화 | 인터뷰의 하단 탭 발견 실패·가입 후 마이페이지 혼란. 현재 일부 패치됐으므로 재검증 포함 | 설명 없이 피드·AI·마이의 차이를 알고 목표 화면 이동 |
| 2 / U02 | 사연에서 AI를 찾기 어렵고 무엇을 해주는지 모름 | 상세의 AI 진입 CTA를 결과·댓글과 구분, 행동을 설명하는 한 줄 | 이번 확정 범위의 핵심. 버튼 단순 확대보다 의미 전달도 필요 | 버튼을 발견하고 누르기 전에 예상 결과 설명 가능; ai_entry_click→chat_open |
| 3 / U03 | 상황/공감이 어떤 반응을 주는지 구분 어려움 | 모드별 '누가 답하는지 / 무엇을 기대하는지' 설명, 선택 결과의 첫 응답 예시 | 인터뷰 두 사람의 기대가 달랐음. 모드 오해는 대화 만족도 해석까지 흔듦 | 선택 이유와 실제 답변 기대 일치; 모드별 취소·도움 응답 |
| 4 / U04 | 등록·전송 이후 처리중/완료/실패를 구분하기 어려움 | 사연 저장중·완료 상세·실패 초안, 댓글 중복 방지, AI 대기·실패·재시도 상태 | 현재 코드의 거짓 성공과 직접 연결. 시각 개선만으로 해결되지 않음 | 성공은 실제 저장; 실패해도 입력 보존; 재시도 완료 1회 |
| 5 / U05 | 나가기·마무리·삭제·숨김의 의미 혼동 | 화면 닫기/대화 보존/영구 삭제의 이름과 확인 구분, 숨기기 2종 분리 | 과거 의도치 않은 삭제 관찰과 현재 숨김 구현 결함 | 취소 시 데이터 변화 0; 사연/대화가 어디 남는지 설명 가능 |
| 6 / U06 | AI를 쓰기는 했지만 실제 도움을 받았는지 알 수 없음 | 확정: 종료 시 선택형 도움 평가 1문항 저장 + 짧은 인터뷰 | 3턴·체류 시간만으로 가치 증명 불가 | 노출·응답·도움 정도·미응답 분리. 문구·선택지·보관 세부는 시안 검토 |
| 7 / U07 | 주간/실시간 랭킹·HOT·0표·내 글 투표 제한이 헷갈림 | 정보 이름·기준·빈 상태·참여 제한 안내 일관화 | Notion 관찰 있음; 현재 랭킹·0표 표시는 일부 수정됨 | 해당 영역의 뜻과 본인 참여 가능 여부를 오해하지 않음 |
| 8 / U08 | 내 기록을 다시 찾거나 닉네임 변경을 확인하기 어려움 | 내 사연·댓글·투표에서 원문 이동, 닉네임 편집/저장·실패 일치 | 핵심 과업 이후의 복원·신뢰와 연결 | 원문 이동 가능, 닉네임 다른 기기 반영 |
| 9 / U09 | 알림·구독이 실제 되는 것처럼 보임 | 제목 가까이 준비 중 표시, 실행 가능한 동작과 준비 중 동작 구분 | 사용자 D05 선택; 신뢰와 측정 혼동 방지 | 클릭했을 때 준비 중 안내, 결제/알림 성공 이벤트 없음 |
| 10 / U10 | 신고가 접수됐다고 해도 운영자가 볼 곳이 없음 | AI 오류 신고를 실제 접수 경로에 연결, 접수/실패 표시 | 현재 `console.log`만 존재. 운영 기능 정상화 필수 | 접수 데이터·권한·운영 조회·실패 복구 확인 |
| 11 / U11 | 모바일 입력·고정바·스크롤·키보드에서 어려움 가능 | 실제 폰의 입력창 가림·탭 발견성·모달/배너 포커스 점검 | 과거 피드백 있고 현재 브라우저 재검증은 없음 | 모바일 Safari/Chrome와 키보드 핵심 과업 완주 |
| 12 / U12 | 서비스가 약속하는 도움의 표현이 일관되지 않음 | '감정 배출/공감'과 '논리 대결/모든 갈등의 해답' 문구 정리 | 현재 빈 피드·작성 안내는 강한 해결 약속을 함. 인터뷰에서는 원치 않는 판단 우려 | 사용자가 기대한 도움과 모드·화면 약속 일치 |

단순 색상·장식 전체 교체는 현재 근거만으로 U01~U04보다 먼저 둘 이유가 없다. 실제 시안에서 대비·가독성이 문제를 일으킨다면 해당 부분은 즉시 높은 우선순위로 올린다.

## 3. 처음 만들 시안의 범위

독립 화면을 많이 만드는 것보다 아래 흐름을 이어서 비교한다. 각 행은 현재 컴포넌트와 연동되므로 구현 담당자가 바뀌어도 추적할 수 있다.

| 화면 묶음 | 꼭 그릴 상태 | 핵심 질문 | 연결 이벤트 |
|---|---|---|---|
| A. 홈·탭·상세 진입 | 신규 방문/둘러보기/로그인, 데이터 로딩/빈 목록/오류 | 첫 행동은 보이고 현재 위치는 분명한가? | page_view, nav click, story_view |
| B. 사연 상세→AI | 투표 전/후, 내 글/남의 글, 게스트/로그인, AI 진입 버튼 | AI가 어떤 도움을 주며 지금 왜 누르는가? | ai_entry_click, action_blocked |
| C. AI 모드·설정 | 상황/공감 선택, 시작점/공감 설정, 뒤로가기·취소 | 선택한 상대와 반응을 예상할 수 있는가? | mode, opening/settings, chat_open |
| D. 채팅·결과 | 첫 응답 대기, 정상, 부분 실패·재시도, 마무리·보존, 선택 평가 1문항 | 기다리는 중인지 실패했는지 알고, 원하는 결과를 얻었는가? | request result, turn1/turn3, finish, feedback |
| E. 작성·삭제·숨김 | 초안/입력 오류/검사중/저장중/실패/성공 상세, 삭제 확인, 숨김 2종 | 내가 한 행동과 실제 데이터 변화가 같은가? | publish/operation result, hide/private |

### U02~U03 문구 후보 — 아직 확정 아님

- AI 진입: **'이 사연으로 AI와 대화하기'**. 짧은 설명 후보: '상대와 대화를 연습하거나, 내 마음을 정리해 보세요.'
- 상황 모드: **'상대와 대화 연습'**. 설명 후보: '사연 속 상대의 입장에서 답해요. 현실에서 할 말을 연습할 수 있어요.'
- 공감 모드: **'내 마음 이야기하기'**. 설명 후보: '사연을 바탕으로 이야기를 들어줘요. 원하는 반응을 선택할 수 있어요.'

한계: 현재 공감 설정에는 '상대편 100%'도 있어 '무조건 내 편'이라는 설명은 실제 모든 선택과 맞지 않는다. 문구를 고르기 전에 현재 모드/설정의 의미와 맞는지 사용자에게 확인한다. 여기서 제시한 설명을 실제 AI 답변의 보장으로 쓰지 않는다.

### U05 숨김 두 기능의 경계 — 확정 정책과 남은 상세

| 기능 | 확정한 의미 | 설계 추천 | 남은 질문 |
|---|---|---|---|
| 나에게만 숨기기 | 해당 사용자에게만 안 보임 | 사용자-사연 관계에 저장, 다른 사용자 피드/조회권한 변경 없음 | 숨긴 목록/해제 위치, 본인 글에도 제공할지 |
| 작성자 비공개 | 작성자가 자기 사연 공개를 거둠. 댓글·투표 보관/재공개 복원, 기존 AI 이용 허용/새 생성 차단 | 사연 공개 상태와 서버 읽기 권한으로 처리; 개인 숨김과 분리 | 비공개 확인 문구, 기존 참여자 내역 표시 방식 |

비공개는 피드에서 카드만 숨기는 것으로 완료되지 않는다. 공유 링크·랭킹·API 원문·댓글은 타인에게 공개하지 않으면서, 기존 대화 소유자의 AI 이용은 허용하는 계약을 구분해야 한다. 현재 로컬 SQL은 사연/댓글을 공개 조회하도록 돼 있어 서버 계약 검증이 먼저다.

기존 AI 대화 이용을 허용하므로 비공개 이전에 그 대화에 포함된 사연 내용도 남을 수 있다. 작성자에게 이 범위를 알리는 안내를 시안에 포함한다. 안내 문구 후보: '사연과 댓글은 다른 사람에게 보이지 않아요. 이미 생성된 AI 대화는 유지되며 계속 이용할 수 있어요.' 이 문구 자체는 아직 검토 후보다.

구현 시 '새 대화'와 '기존 대화 재진입'은 서버에 저장된 대화방의 존재·소유권을 기준으로 구분한다. 현재 프론트엔드는 다시 열 때도 새 `ChatSession` 객체를 만들므로, 화면 세션 ID가 새로 생겼다는 이유만으로 이어하기를 차단하면 확정 정책과 어긋난다. 다른 모드/설정 변경이 새 대화 생성에 해당하는 경계는 상세 시안에서 설명하고 확인한다.

| 19금/욕설 필터 오류 | 검사 API 있으나 공급자 실패를 안전 판정처럼 반환 가능 | 오탐·누락·실패를 분리하고 실패 정책부터 질문 |
| 같은 밸런스 투표 재클릭 취소 요청 | 현행은 같은 쪽 무시, 반대쪽으로 1회 변경 | 인터뷰 요청을 승인된 정책으로 간주하지 않고 사용자에게 별도 확인 |

## 6. 다음 세션에서 바로 시작할 작업

1. Q01~Q03은 D08~D10으로 확정했다. 비공개·재공개·기존 대화 이용·선택 평가를 해당 정책대로 시안과 검증 과업에 연결한다.
2. U01~U04 연결 시안을 준비한다. 현행 구조를 바탕으로 성공/실패 상태까지 검토하며, 브랜드 전체 개편이나 신규 AI 단독 경로로 확장하지 않는다. Q04 이후의 미결정 항목은 필요한 작업 전에 질문한다.
3. 시안에 `button_id`, 기대 결과, 관련 T/Q 케이스를 붙여 사용자 검토본으로 만든다.
4. 사용자 검토 후 실제 구현 요청이 오면 [실행 계획](README.md)의 W2~W4를 진행한다.

이번에 시간이 드는 코드·이벤트·문서 대조와 소스 목록 추출은 수행했다. 현재 미결정은 분석을 덜 해서가 아니라 사용자가 선택해야 의미가 정해지는 항목이다.
