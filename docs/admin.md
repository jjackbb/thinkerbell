# 운영자 계정

문의에 답변하려면 운영자 권한이 필요하다. 누가 운영자인지는 `admins` 테이블이 정한다.

최종 수정: 2026-08-20

---

## 1. 현재 등록된 운영자

| 이메일 (로그인 아이디) | 닉네임 | 등록일 |
|---|---|---|
| `master@master.master` | 운영자 | 2026-08-20 |

**운영 전용 계정이다.** 개인 계정에 권한을 붙이지 않은 이유는, 담당자가 바뀌어도 계정만
넘기면 되고 개인 활동과 운영 권한이 섞이지 않기 때문이다.

**비밀번호는 이 문서에 적지 않는다.** 저장소에 평문으로 남기면 저장소를 볼 수 있는
사람이 곧 운영자가 된다. 팀 비밀번호 관리 도구나 별도 경로로 전달할 것.

> ### ⚠️ 배포 전에 확인할 것
>
> - 이 계정은 **모든 사용자가 보낸 문의를 읽을 수 있다.** 서비스를 실제로 열기 전에
>   충분히 강한 비밀번호인지 확인할 것. 바꾸는 곳은
>   **마이 → 계정 설정 및 정보 → 비밀번호 변경**.
> - `master.master`는 실제로 메일을 받는 주소가 아니다. **비밀번호를 잊으면 메일로
>   재설정할 수 없다.** Supabase 대시보드(Authentication → Users)에서 직접 바꿔야 한다.

## 2. 운영자가 할 수 있는 것 / 없는 것

권한은 문의에만 열려 있다. 나머지는 운영자여도 본인 것만 보인다.

| 대상 | 운영자 | 근거 |
|---|---|---|
| 다른 사람의 **문의** 읽기 | ⭕ | `inquiries_select_admin` |
| 다른 사람의 문의에 **답변** 쓰기 | ⭕ | `inquiries_update_admin` |
| 다른 사람의 **AI 대화** | ❌ 본인 것만 | `ai_personas`는 본인 정책뿐 |
| 다른 사람의 **무료 횟수 기록** | ❌ 본인 것만 | `ai_chat_usage`는 본인 정책뿐 |
| 다른 사람의 **신고 내역** | ❌ 본인 것만 | `reports`는 본인 정책뿐 |
| **운영자 목록** 조회 | ❌ 아무도 못 읽음 | `admins`에 정책이 하나도 없음 |

**AI 대화는 운영자도 볼 수 없다.** 이 서비스에서 가장 사적인 데이터라 일부러 열어두지
않았다. 나중에 신고 처리 등으로 열어야 할 일이 생기면, 여는 범위와 근거를 여기에 남길 것.

## 3. 운영자 등록 / 확인 / 해제

Supabase SQL Editor에서 실행한다.

**등록**

```sql
insert into public.admins ("userId")
select id from auth.users where email = '운영자이메일'
on conflict do nothing;
```

**확인** (지금 누가 운영자인가)

```sql
select u.email, u.raw_user_meta_data->>'nickname' as 닉네임, a."createdAt"
from public.admins a join auth.users u on u.id = a."userId";
```

**해제**

```sql
delete from public.admins a
using auth.users u
where u.id = a."userId" and u.email = '운영자이메일';
```

등록/해제 후 해당 사용자가 **앱을 새로고침**해야 메뉴가 나타나거나 사라진다.
권한 판정은 로그인 시 `is_admin()`을 한 번 호출해 이뤄진다.

---

## 4. 쓰는 법

1. 운영자 계정으로 로그인
2. **마이 → 문의 관리** (운영자에게만 보이는 검은색 메뉴)
3. 답변 대기 건이 배지로 표시된다. 답변을 적고 '답변 보내기'
4. 문의한 사람은 **마이 → 도움말 및 문의 → 내 문의 내역**에서 답변을 본다

---

## 5. 알아둘 것

- **답변이 달려도 사용자에게 알림이 가지 않는다.** 직접 들어와 봐야 안다.
  메일 발송 수단이 없어서 앱 안에서만 주고받는다. 알림 기능이 생기면 붙일 것.
- 사용자는 자기가 보낸 문의를 **수정하거나 지울 수 없다** (해당 RLS 정책 없음).
  접수된 내용이 바뀌면 처리가 어렵기 때문이다.
- 계정을 탈퇴하면 그 사람의 문의도 함께 사라진다 (`on delete cascade`).
