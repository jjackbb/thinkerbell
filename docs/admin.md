# 운영자 안내

**2026-09-30 운영 권한 이전 완료:** 사용자가 “A 네이버에 운영 권한 부여 및 기존 가상 계정의 운영 권한 해제 승인”을 명시했다. 대상 A의 이메일 확인 상태·기존 운영자 1명·기존 가상 도메인을 조건으로 한 트랜잭션에서 A 등록과 기존 역할 해제를 수행했다. 운영자 1명/A 일치, 기존 역할 없음/기존 Auth 계정 보존, B 일반 계정을 조회했다. A Preview 새로고침 후 마이 → 문의 관리에서 보존한 기술 시험 문의를 확인했고 B에는 운영자 메뉴가 없다. 다른 문의 내용·답변·계정·데이터는 변경하지 않았다. 시험 문의 한 건은 확인 근거로 유지한다. 운영자 계정 이전은 실제 운영 DB에 적용된 변경이며 Preview 전용 권한이 아니다. 이후 일반 사용자 역할 경계 시험에는 B를 사용하고 A는 운영자로 구분한다.

아래는 이전 계정의 문제를 확인하고 권한 이전을 승인받기 전의 이력이다. 현재 운영자는 A 네이버 계정이며, 기존 가상 계정으로 로그인하거나 이메일 재설정을 시도하지 않는다.


**2026-09-30 운영자 복구 정정:** 사용자가 기존 운영자 주소는 실제 수신 가능한 이메일이 아니며 비밀번호도 모른다고 알렸다. `docs/admin.md`의 2026-08-20 기록에도 수신 불가·이메일 재설정 불가가 명시돼 있었고, 현재 지정 계정과 그 기록의 일치를 내부 비교로 확인했다. AI가 이 근거를 먼저 확인하지 않고 로그인·재설정을 안내한 점을 정정한다. 기존 로그인 창의 주소를 비우고 선택 대기로 변경했다. 재설정 메일·비밀번호 변경·운영 권한 변경은 하지 않았다.

**준비한 해결안:** 소유 확인·재설정을 마친 A 네이버 계정으로 운영 권한 이전을 추천한다. A의 Auth 이메일 확인 상태와 현재 일반 계정임을 읽기 확인했다. 사용자가 선택하면 니편내편 DB 한 트랜잭션에서 A 등록과 기존 가상 계정의 운영 역할만 해제하고, 기존 계정·데이터를 보존한다. 이후 A의 `is_admin=true`·기존 대상 역할 해제·운영자 1명·문의 화면을 확인한다. B는 일반 계정으로 유지한다. 별도 실제 운영 전용 이메일을 준비하는 선택지도 있다. 실제 운영 권한 대상 결정이므로 아직 실행하지 않았다. 현재 `is_admin()`을 참조하는 RLS는 문의 조회·수정 두 정책이며 다른 사람의 AI 대화 권한은 추가하지 않는다.

권한 이전 실행 계약(선택 후에만 실행): 기존 운영자 수가 1이고 대상 A가 이메일 확인된 지정 계정인지 다시 대조한다. 한 트랜잭션에서 두 대상에 한정해 등록·해제를 수행하고 예상 행 수가 다르면 롤백한다. 기존 Auth 계정 삭제, 비밀번호 강제 변경, 개인 데이터 수정은 포함하지 않는다. 이 변경은 운영 DB의 실제 권한 이전이며 Preview 화면에만 한정되지 않는다. A는 이후 일반 사용자 권한 경계 시험의 대상에서 제외하고 B를 일반 사용자로 유지한다.


최신 운영 기준은 [PLAN.md](../PLAN.md)입니다. 사용자가 매일 신고·문의·AI 오류를 확인합니다. 아래 계정·RLS 설명은 2026-08-20 기록이며 현재 원격 권한은 미확인입니다. 실제 운영 점검을 대신하지 않습니다.

문의에 답변하려면 운영자 권한이 필요하다. 누가 운영자인지는 `admins` 테이블이 정한다.

## 1. 과거 등록 기록 — 현재 상태 재확인 필요

| 이메일 (로그인 아이디) | 닉네임 | 등록일 |
|---|---|---|
| `master@master.master` | 운영자 | 2026-08-20 |

**운영 전용 계정이다.** 개인 계정에 권한을 붙이지 않은 이유는, 담당자가 바뀌어도 계정만
넘기면 되고 개인 활동과 운영 권한이 섞이지 않기 때문이다.

**비밀번호는 이 문서에 적지 않는다.** 저장소에 평문으로 남기면 저장소를 볼 수 있는
사람이 곧 운영자가 된다. 팀 비밀번호 관리 도구나 별도 경로로 전달할 것.

> ### ⚠️ 배포 전에 확인할 것
>
> - 이 계정은 **모든 사용자가 보낸 문의를 읽을 수 있다.** 서비스를 실제로 열기 전에
>   충분히 강한 비밀번호인지 확인할 것. 바꾸는 곳은
>   **마이 → 계정 설정 및 정보 → 비밀번호 변경**.
> - `master.master`는 실제로 메일을 받는 주소가 아니다. **비밀번호를 잊으면 메일로
>   재설정할 수 없다.** Supabase 대시보드(Authentication → Users)에서 직접 바꿔야 한다.

## 2. 과거 기록의 권한 범위 — 현재 원격 검증 전

권한은 문의에만 열려 있다. 나머지는 운영자여도 본인 것만 보인다.

| 대상 | 운영자 | 근거 |
|---|---|---|
| 다른 사람의 **문의** 읽기 | ⭕ | `inquiries_select_admin` |
| 다른 사람의 문의에 **답변** 쓰기 | ⭕ | `inquiries_update_admin` |
| 다른 사람의 **AI 대화** | ❌ 본인 것만 | `ai_personas`는 본인 정책뿐 |
| 다른 사람의 **무료 횟수 기록** | ❌ 본인 것만 | `ai_chat_usage`는 본인 정책뿐 |
| 다른 사람의 **신고 내역** | ❌ 본인 것만 | `reports`는 본인 정책뿐 |
| **운영자 목록** 조회 | ❌ 아무도 못 읽음 | `admins`에 정책이 하나도 없음 |

**AI 대화는 운영자도 볼 수 없다.** 이 서비스에서 가장 사적인 데이터라 일부러 열어두지
않았다. 나중에 신고 처리 등으로 열어야 할 일이 생기면, 여는 범위와 근거를 여기에 남길 것.

## 3. 운영자 등록 / 확인 / 해제

아래는 과거 관리 SQL 참고입니다. 실제 프로젝트·스키마·권한을 확인하고 허용된 운영 작업에서만 실행합니다. 이번 폴더 정리에서는 실행하지 않았습니다.

**등록**

```sql
insert into public.admins ("userId")
select id from auth.users where email = '운영자이메일'
on conflict do nothing;
```

**확인** (지금 누가 운영자인가)

```sql
select u.email, u.raw_user_meta_data->>'nickname' as 닉네임, a."createdAt"
from public.admins a join auth.users u on u.id = a."userId";
```

**해제**

```sql
delete from public.admins a
using auth.users u
where u.id = a."userId" and u.email = '운영자이메일';
```

등록/해제 후 해당 사용자가 **앱을 새로고침**해야 메뉴가 나타나거나 사라진다.
권한 판정은 로그인 시 `is_admin()`을 한 번 호출해 이뤄진다.

## 4. 쓰는 법

1. 운영자 계정으로 로그인
2. **마이 → 문의 관리** (운영자에게만 보이는 검은색 메뉴)
3. 답변 대기 건이 배지로 표시된다. 답변을 적고 '답변 보내기'
4. 문의한 사람은 **마이 → 도움말 및 문의 → 내 문의 내역**에서 답변을 본다

## 5. 알아둘 것

- **답변이 달려도 사용자에게 알림이 가지 않는다.** 직접 들어와 봐야 안다.
  메일 발송 수단이 없어서 앱 안에서만 주고받는다. 알림 기능이 생기면 붙일 것.
- 사용자는 자기가 보낸 문의를 **수정하거나 지울 수 없다** (해당 RLS 정책 없음).
  접수된 내용이 바뀌면 처리가 어렵기 때문이다.
- 계정을 탈퇴하면 그 사람의 문의도 함께 사라진다 (`on delete cascade`).

## 최신 계획을 위해 확인할 차이

- 기존 문의 관리 코드는 `frontend/src/lib/inquiries.ts`, 화면은 `frontend/src/components/MyPageView.tsx`입니다. 폴더 정리에서 권한을 추가하지 않았습니다.
- 신고·AI 오류가 실제 운영 목록에 접수되고 담당자가 조회할 수 있어야 합니다. 위 과거 표의 신고 제한과 최신 요구의 차이는 구현·권한 검증 대상으로 남깁니다.
- 도움 평가는 본인·운영자만 접근, 최대 30일·대화 삭제/탈퇴 시 함께 삭제가 확정입니다. 이 권한이 이미 구현되었다고 간주하지 않습니다.
- PLAN의 이메일 확인 가입에 맞춰 실제 외부 메일 수신·복귀를 검증해야 합니다. 과거 운영 계정만으로 인증 메일 검증을 대신하지 않습니다.
- 운영자라고 일반 AI 대화 전체를 읽을 권한을 임의로 추가하지 않습니다.
