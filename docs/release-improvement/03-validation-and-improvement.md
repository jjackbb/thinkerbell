# 기능 검증과 공개 후 개선 기준

정책은 [PLAN](../../PLAN.md) §4~5, 실제 결과는 [실행 기록](../plan-execution/2026-09-28-in-progress-release-preflight.md)입니다. 이 문서는 기대 결과이며 모든 항목이 미실행 또는 통과라는 선언이 아닙니다. [이전 상세 T/Q 시나리오](../../archive/2026-09-30/current-docs-before-cleanup/docs/release-improvement/03-validation-and-improvement.md)는 당시 참고 근거로 보존했습니다.

## 변경 영향에 맞춘 검증

작은 가역 변경에는 테스트를 새로 만들지 않습니다. 통과한 검사는 새 변경·실패·미해결 문제가 없는 한 반복하지 않습니다. 기록에는 버전·환경·행동·기대·실제·PASS/FAIL/NOT_RUN/BLOCKED·근거를 남깁니다. 실제 공급자/DB 연동·오류 주입·사용자 보고·직접 관찰을 구분합니다.

| 영역 | 확인 기준 |
| --- | --- |
| 가입·계정 | 소유 확인 메일 실제 도착·복귀, 신규/기존 안내, 분리 로그인·세션 교체. 접수만으로 수신 성공을 주장하지 않음 |
| 저장·참여 | 사연·댓글 서버 성공 후 표시, 실패 초안 보존, 재시도 중복 0, 투표/공감 규칙 준수 |

## 계측 확인

- 동의 전·거부·철회 후 외부 요청 0, 분석 오류가 제품 사용을 막지 않음.
- 핵심 과업·AI 저장 결과만 허용. 화면 이동 수동 page_view와 전체 클릭 수집은 제외.
- 정상 답변 완료와 저장 결과를 구분하고 재시도·재렌더·같은 요청 복구의 중복을 확인.
- release_id·신규/이어하기·유입 범주가 실제 행동과 맞고 원문·내부 ID·임의 속성이 없음을 확인.
- 수집 HTTP 응답·GA4 Realtime/DebugView·처리 보고서는 다른 확인 단계. 기술 시험은 성과에서 제외.
- 분석 동의로 관측된 세션의 사연 조회 → 첫 정상 답변 도달률을 같은 기간·배포에서 계산. 신규/이어하기를 구분하고 실제 분자·분모를 표시.

## 배포와 복구

현재 대상과 절차는 [운영 반영 안내](../plan-execution/2026-09-28-release-gates.md)를 따릅니다. Vercel 연결은 `.vercel/project.json`에 있고, Supabase 프로젝트는 `vzhyhadjtaqbapicjrco`입니다. 연결 접근은 실행할 때 확인합니다. 과거 MCP 오류를 현재 장애로 단정하지 않습니다.

운영 DB의 직접 쓰기는 이미 차단됐습니다. 옛 브라우저 직접 쓰기 앱으로 단독 롤백하지 않습니다. 데이터 노출·손실·핵심 저장 장애면 해당 변경을 멈추고 호환되는 검증 배포로 복구합니다.

## 실제 게시 이후

1. 커뮤니티·SNS 소개 글과 링크를 게시하고 경로·시각·게시물 주소·배포 버전을 기록합니다. 직접 모집·동석 관찰은 선행 조건이 아닙니다.
2. 처리된 보고서와 자발적 피드백을 대조합니다. 미수신과 이탈을 혼동하지 않고 기술 시험을 제외합니다.
3. 확인된 문제 하나와 개선 전 판정 기준을 정합니다. 변경·관련 검증·배포 후 같은 기준으로 재확인합니다.
4. 기능 수정 확인·사용성 관찰·정량 변화·표본 부족을 구분합니다. 실제 관찰·인터뷰를 하지 않았다면 했다고 쓰지 않습니다.

평가 4~5점/유효 응답 비율은 응답자 범위의 지표입니다. 개인 평가 최대 30일, 장기 보존은 월말 서로 다른 응답자 5명 이상을 증명한 월 전체 모드 합계만 허용합니다. 전 점수 분포를 장기 보존하지 않습니다. 목표값·실제 표본 수·개선 효과를 임의 생성하지 않습니다.
