# UX 상세 기준과 남은 선택

최신 계획은 [PLAN.md](../../PLAN.md)입니다. 이 문서는 계획을 화면별 검토에 연결하는 참고 자료입니다. 아래 정책 정리는 확정 사항이며 화면 시안·기능 구현 완료를 뜻하지 않습니다. 수정 전 U01~U12·Q01~Q15와 후보 문구는 [원본](../../archive/2026-09-22/before-alignment/docs/release-improvement/04-ux-priorities-and-decisions.md)에 보존했습니다.

## 확정 사항과 검토 순서

| PLAN 순서 | 화면·상태 | 구현·검토 기준 |
|---|---|---|
| 1. 저장·등록 | 사연·댓글·닉네임·신고의 대기/성공/실패 | 서버 성공 후 완료 표시, 실패 입력 보존·재시도 |
| 2. 현재 위치·AI 발견 | 활성 탭·사연 상세 | 댓글을 오래 탐색하지 않아도 AI 발견, 투표는 AI 진입 필수 아님 |
| 3. 모드 이해 | 상대와 대화하기 / 공감 대화 | 사연 속 상대 역할의 AI임을 설명. 공감 대화는 내 입장·양쪽·상대 입장 중심 선택 설명 |
| 4. 대기·실패·복원 | 첫 요청/부분 실패/재시도/저장 실패/이어하기 | 포텐스만 사용. 입력 보존·실제 재시도, 새로고침·다른 기기 복원 |
| 5. 마무리·평가 | 대화 보존·5점 평가·건너뛰기·제출 실패 | “이 AI 대화가 도움이 되었나요?” 1문항. 기분·한 줄 소감 제거. 정상 답변 후 명시적 마무리에 노출 |
| 6. 개인 기록·운영 | 내 기록·숨긴 목록·신고·문의 | 숨김 즉시 취소·마이페이지 복원. 실제 운영 접수와 실패 표시 |

랭킹·투표 제한·빈 화면·준비 중 안내는 실제 동작에 맞춘다. 모바일 키보드·스크롤·뒤로가기를 핵심 흐름에 포함한다. 전체 디자인 교체나 AI 단독 신규 진입은 이번 범위에 추가하지 않는다.

## 이전 질문 중 PLAN에서 해결된 것

| 기존 ID | 확정된 내용 |
|---|---|
| Q01 | 작성자 비공개 중 댓글·투표 보관, 타인 원문·참여 차단, 재공개 시 중복 없이 복원 |
| Q02 | 기존 소유 AI 대화 이용 허용. 타인의 신규 생성 차단, 작성자는 자기 비공개 사연으로 생성 가능. 공감 관점 변경은 보존 맥락 사용 |
| Q03·Q15 일부 | 도움 평가 5점·건너뛰기·이용 구간별 1건·최대 30일·본인/운영자 접근·대화 삭제/탈퇴 시 함께 삭제. 기존 기분·소감 제거 |
| Q04 | 첫 공개 성인 콘텐츠 기능 보류: 신규 등록·공개 노출·관련 AI 차단, 기존 자료 임의 삭제 없음 |
| Q05 | 검사 실패는 안전 판정 아님. 입력 보존·포텐스 실제 재검사, 수정 내용 재검사 |
| Q06 | 같은 투표 재클릭 무시·반대쪽 1회 변경·취소 없음·본인 투표 제한 |
| Q07 | 개인 숨김 즉시 취소와 마이페이지 숨긴 목록 복원 |
| Q09 이름 | 상대와 대화하기 / 공감 대화 |
| Q12 운영 조건 | 공개·직접 모집 병행, 기간·모집 인원을 출시 조건으로 두지 않음. 월 예산 상한 10만 원. 메일·도메인 구성은 PLAN §1 |
| Q14 | 사용자가 매일 신고·문의·AI 오류 확인 |

비공개 안내에는 이미 생성된 타인의 AI 대화에 포함된 내용이 남을 수 있음을 명시한다. 평가 응답값은 GA4 제외이며 동의 후 계측한다. 대표 이벤트는 `ai_chat_turn1`로 확정했다.

## 남아 있는 선택·미확인

이 항목들은 이번 폴더 정리를 막지 않습니다. 관련 화면·운영 작업을 시작할 때 근거·구체안을 준비하고 사용자에게 질문합니다. 무응답을 승인으로 처리하지 않습니다.

| 항목 | 아직 정하지 않거나 확인하지 않은 범위 |
|---|---|
| Q08·Q10·Q09 세부 | 준비 중 안내의 화면 방식, 빈 화면의 실제 문구, 모드 설명의 상세 배치·예시 |
| Q11 | 실제 Vercel·DB·GA4 소유 계정/접근, 메일 발송 구성·가격·계정 사용량 |
| Q12 모집 세부 | 모집 채널·실행 일정. 인원·고정 기간은 출시 조건이 아님 |
| Q13 | 과거 Notion 2인 기록의 실제 실시일·추가 결과 존재 |
| Q15 잔여 | 평가 외 기존 계정·대화 전체의 보관 정책과 현재 원격 구현 차이. 이번 정리에서 임의 변경하지 않음 |

## 기존 인터뷰 문제와 구현의 대조


출처: [Notion 인터뷰](https://app.notion.com/p/3a9626093f2e80439a91f9946d6c5ba3), [과거 패치](../CHANGELOG.md), 현재 코드. **과거 수정 기록만으로 사용자 문제 해결이라고 판정하지 않는다.**

| 과거 관찰 | 현재 코드/기록 | 다음 행동 |
|---|---|---|
| 가입 후 남의 투표/AI 대화가 보임 | 샘플 수치 제거·계정별 대화 분리 패치 기록; 로그아웃 시 개인 state 제거 코드 | 신규/계정 교체/다른 기기 회귀검증. 데모 자료를 현행 결함으로 단정하지 않음 |
| 사연 등록 후 못 찾음 | 등록 후 피드 상세를 여는 구현 있음 | 서버 성공 시점·스크롤·사용자 발견성 재검증; 실패 처리 먼저 고치기 |
| 삭제가 바로 실행됨 | 사연 삭제 확인 모달, 대화 마무리 보존 패치 있음 | 실제 눌렀을 때 취소/확인·마무리/삭제 구분 확인 |
| 댓글 중복 등록 | 낙관적 삽입·Realtime 처리 있음, DB 오류 미확인 | 연타·중복 수신·재시도별 재현하고 원인 분리 |
| 랭킹 혼동 | 주간/실시간 배너는 구현됨, HOT 별도 정렬 | 이름·기준을 사용자가 이해하는지 검사 |
| 하단 탭·AI 버튼 못 찾음 | 버튼이 코드에 존재하고 일부 헤더/가림 문제 패치 | 존재만으로 발견성을 보장하지 않음. 현재 시안에서 다시 과업 관찰 |
| 19금/욕설 필터 오류 | 검사 API 있으나 공급자 실패를 안전 판정처럼 반환 가능 | 오탐·누락·실패를 분리하고 입력 보존·포텐스 실제 재검사라는 확정 정책 검증 |
| 같은 밸런스 투표 재클릭 취소 요청 | 현행은 같은 쪽 무시, 반대쪽으로 1회 변경 | 인터뷰 요청을 승인된 정책으로 간주하지 않고 현행 유지라는 PLAN 확정 정책 적용 |


## 화면 검토에 붙일 항목

각 화면의 목적·버튼·선행 조건·성공·실패·취소·이벤트·검증 케이스를 함께 검토한다. [이벤트 명세](02-events-and-buttons.md)와 [검증 명세](03-validation-and-improvement.md)를 사용하며 별도 실행 순서는 만들지 않는다. 다음 실행 단계는 PLAN §4에서 확인한다.
