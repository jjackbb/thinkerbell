## 소스 목록과 재현 환경의 빈틈

[source-interactions.csv](source-interactions.csv)는 TypeScript AST로 TSX 24개를 읽어 생성했다. 정적 `<button>` 위치 153곳, DOM 상호작용/컨트롤 행 227개, 컴포넌트 콜백 연결 행 71개다. DOM `onClick`은 162곳이고 폼 `onSubmit`은 8곳이다. 컴포넌트 콜백은 실제 버튼과 별도이며 합쳐서 버튼 수라고 부르지 않는다. 반복 목록·조건부 노출·동적으로 바뀌는 선택지는 브라우저 대조가 필요하다. 현재 이 프로젝트에 Playwright/Puppeteer는 설치돼 있지 않아 이번 시각·브라우저 검증은 NOT_RUN이다.

앱의 리터럴 `.from()`/`.rpc()` 호출을 로컬 migration 생성문과 대조한 결과:

| 구분 | 로컬 생성문 있음 | 로컬 생성문 없음 — 운영 정의 대조 필요 |
|---|---|---|
| 테이블 | stories, comments, votes, events | ai_personas, ai_chat_usage, inquiries |
| RPC | vote_story, like_comment, increment_story_view, submit_report, submit_appeal | balance_game_state, vote_balance_game, delete_my_account, is_admin |

이 표는 함수/테이블 정의의 존재 검사이며, migration의 실행 성공·현재 DB와 동일성·권한 안전성 검증은 아니다.

비스트리밍 `/api/chat`에는 키가 없을 때 `source: simulation`인 고정 응답 경로도 남아 있다(`api/index.ts:111`). 현재 주 채팅은 `/api/chat-stream`을 사용한다. 두 API 모두 같은 성공/실패 계약으로 정리하고, 데모 응답은 실제 AI 성공 이벤트에서 제외한다.

## 기존 측정으로 바로 결론 내리면 안 되는 이유

1. `events_name_check`와 TypeScript 타입은 9개만 허용한다. 이벤트를 추가할 때 코드만 고치면 DB는 거절한다.
2. 기존 날짜 조건은 시작일만 있고 종료일·시간대·테스트 제외가 없다. 이후 방문이 계속 합쳐진다.
3. 기존 SQL은 이벤트별 서로 다른 탭 수를 세는 **도달 집계**다. 같은 사람이 같은 사연에서 순서대로 완주했다는 퍼널 검증은 아니다.
4. 피드 카드에서 바로 투표하거나, 투표 없이 AI를 여는 흐름도 있다. `사연상세→투표→AI`를 모든 사람의 필수 경로로 강제하면 정상 이용도 이탈이 된다.
5. 이벤트에 버전·진입 버튼·실패 이유·대기 시간이 없어 '어디서 왜 막히나'의 원인 후보를 충분히 나누기 어렵다.

따라서 오류 수정과 계측 기준 정비가 끝난 릴리스를 **새 기준선 v1**으로 두고, 9월 초 데이터는 당시 정의를 유지한 참고 자료로 별도 분석한다.
