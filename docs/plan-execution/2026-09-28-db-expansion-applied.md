# 운영 DB 호환 확장 적용 — 2026-09-28

> **시점별 근거 문서:** 아래 상태·결정·SQL 안내는 제목 날짜와 후속 기록 당시의 이력입니다. 현재 작업 지시는 [최신 인수인계](README.md)와 [PLAN](../../PLAN.md)을 따릅니다. 과거 미적용·미실행 표시만 보고 재실행하지 않습니다.


대상은 니편내편 Supabase 프로젝트 `vzhyhadjtaqbapicjrco`다. 이 문서는 [PLAN](../../PLAN.md)의 운영 전환 상태를 기록한다. 작성자 비공개, AI 횟수·평가, 투표의 **DB 구조와 서버 전용 함수는 적용**됐다. 새 앱은 아직 배포하지 않았고 직접 쓰기 권한도 닫지 않았다. 따라서 새 기능의 실제 사용자 동작이나 AI 횟수 제한의 운영 강제를 완료했다고 판정하지 않는다.

## 적용 전 확인

- 사연 7건은 모두 공개 상태였고 기존 `isBlind`·`isAdult`·`isHidden` 값이 거짓이었다. 댓글 8건도 모두 블라인드가 아니었다. 본문은 읽지 않았다.
- AI 방은 적용 직전 5개였다. 앞선 7개 집계와 차이가 나는 원인은 확인하지 않았고, 방을 삭제하거나 재분류하지 않았다.
- 같은 사용자·사연·모드 선택의 AI 방 중복, 같은 사용자·사연의 투표 중복 그룹은 각각 0개였다.
- 새 비공개·AI 횟수·평가 테이블은 없었다. 기존 `ai_personas` 직접 INSERT/UPDATE 정책과 `ai_chat_usage` INSERT 정책이 있었다.

## 적용 뒤 확인과 한계

- `stories.visibility`·제약·정책·트리거, 서버 전용 AI 테이블·함수, 두 정리 작업이 존재한다. 비공개 사연은 0건이다.
- 익명 역할의 기존 공개 사연/댓글 수는 7/8로 확인했다. 실제 비공개 사연을 만든 계정별 REST·Realtime 조회는 **NOT_RUN**이다.
- AI 예약·평가 테이블은 0행이며, `anon`·`authenticated`의 직접 SELECT와 새 서버 전용 함수 EXECUTE는 허용되지 않았다. `service_role` 접근은 허용된다.
- **기존 `ai_personas` INSERT/UPDATE와 `ai_chat_usage` INSERT 정책·권한은 유지**했다. 기존 공개 앱 호환을 위한 임시 상태이며, 브라우저 우회 가능성을 없애려면 새 서버 앱의 실제 계정 시험 뒤 직접 쓰기 차단 SQL을 적용해야 한다.
- AI·접근 무효화 정리 작업은 등록·활성화됐지만 첫 예약 시각이 오지 않아 실행 이력은 아직 0건이다. 별도 가입 소유 확인 정리 작업은 조회 시점 35회 모두 성공했다.
- 격리 DB의 [통합 계약 시험](../../tests/plan-release-integration.sql)과 [비공개 경합 시험](../../tests/story-author-private-contract.sql)은 통과했다. 이는 운영의 실제 두 계정·브라우저·포텐스·GA4 시험을 대신하지 않는다.

## 다음 전환 경계
