# 2026-10-20 댓글 입력창 안내: 이용 제한 문구와 실제 기능의 차이

## 요약

사용자 결정으로 댓글·답글 입력창 안내를 아래 문구로 바꿨다(로컬, 미커밋).

> 욕설이나 성적 수치심을 줄 수 있는 표현이 담긴 댓글은 가려지거나 삭제될 수 있고, 반복되면 서비스 이용이 제한될 수 있어요.

문구 중 "가려지거나 삭제될 수 있다"는 지금 있는 기능과 맞다. **"반복되면 서비스 이용이 제한될 수 있다"는 아직 기능과 정책이 없다.** 공개 전에 아래 두 가지를 정하거나, 문구에서 이 부분을 빼야 한다.

## 현재 실제 동작 (저장소 기준)

| 문구 | 실제 | 근거 |
|---|---|---|
| 가려질 수 있다 | 서로 다른 신고자 3명 이상이면 댓글이 자동으로 가려진다(`isBlind`) | `backend/supabase/migrations/20260818020000_report_policy.sql` |
| 삭제될 수 있다 | 운영자가 신고를 확인한 뒤 처리한다 | `PLAN.md` "공개 후 운영: 사용자가 매일 신고·문의·AI 오류 확인" |
| 이용이 제한될 수 있다 | **없음.** 계정 정지·작성 제한 기능이 없고 이용 정책 문서도 없다 | 저장소 검색 결과 없음 |

## 결정·구현이 필요한 것

1. **이용 정책 문서:** 금지 표현, 제한 기준(예: 가려진 댓글 N회), 제한 내용·기간, 이의 제기 방법을 정한다. 앱 안에서 볼 수 있는 위치(마이페이지 도움말 등)도 정한다.
2. **제한 기능:** 운영자가 계정의 사연·댓글 작성을 막는 서버 검사와 DB 기록을 만든다. 서버(`/api/comments`, `/api/stories`)에서 확인해야 하며, 브라우저만으로 막으면 안 된다.
3. 1·2가 공개 전에 준비되지 않으면 문구를 "가려지거나 삭제될 수 있어요"까지로 줄인다.
