# 신규 가입 이메일 확인 시험 — 2026-09-26

이 문서는 [PLAN](../../PLAN.md)의 신규 가입 이메일 확인에 대한 후속 **검증 기록**이다. 기존 [설정 준비 기록](2026-09-25-auth-mail-setup.md)과 [인증 화면 배포 기록](../release-notes/2026-09-25-auth-email.md)은 당시 상태를 보존한다.

## 확인된 결과

| 항목 | 증거와 범위 |
| --- | --- |
| 만료 링크 안내 화면 | 사용자가 `otp_expired`를 흉내 낸 URL에서 “가입 확인 링크를 사용할 수 없습니다.”가 보였다고 확인했다. 실제로 발송된 링크가 만료됐을 때의 재발송 동작까지 검증한 결과는 아니다. |
| 설정 전환 | 사용자가 Supabase의 `Confirm Email`을 켰다고 확인했다. AI는 관리자 설정 화면을 직접 읽지 못했다. 기존 Auth 계정을 일괄 변경하지 않았다. |
| 신규 가입 경로 | 사용자가 `Confirm Email`을 켠 뒤 새 가입→네이버 **받은편지함**에서 인증 메일 수신→앱 복귀 직후 **로그인 상태**까지 확인했다. 사용자가 받은 메일 본문은 영어였다. 이는 사용자 시험 보고이며 AI가 메일함·브라우저를 직접 읽은 결과는 아니다. |
| 니편내편 Auth 집계 | 읽기 전용 Supabase MCP에서 개인정보 없이 `auth.users`를 집계했다. 기존 45명에서 **46명**으로 늘었고, 미확인 0명·확인 시각이 있는 계정 46명이다. 최근 24시간 생성 1명과 그중 확인 1명이다. 가장 최근 생성은 2026-09-26 00:12:55 KST, 확인은 00:13:06 KST다. 사용자 시험과 시간·수량이 일치하지만 어느 메일함을 거쳐 복귀했는지 DB 집계만으로는 알 수 없다. |

이 결과로 **신규 계정 1개의 확인 완료**는 DB에서 확인됐다. 메일 발송·링크·앱 복귀의 실제 이용 흐름은 사용자의 시험 보고다. 과거 45명의 `email_confirmed_at`은 당시 메일 소유권을 확인했다는 증거가 아니다.

## 남은 검증

- 복귀 직후 로그인 상태는 사용자 시험으로 확인됐다. 실제 사연 작성·저장 등 새 계정의 앱 과업은 별도로 시험한다.
- 재발송 메일 수신, 실제 만료 링크에서의 안내·재발송, 다른 메일 환경에서의 전달은 별도로 시험한다.
- Resend 발송 로그와 대시보드의 현재 SMTP·도메인 상태는 이 실행 환경에서 직접 읽지 못했다. 신규 계정 집계는 모든 수신자에게 전달된다는 보증이 아니다.
- [가입 확인 메일 한국어 문안](2026-09-26-auth-email-korean-draft.md)은 준비했으나 운영에 적용·재시험하지 않았다.

키·메일 주소·계정 ID·개인정보는 기록하지 않았다.
