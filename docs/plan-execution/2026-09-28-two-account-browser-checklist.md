# 새 메일함 두 개로 하는 실제 가입·과업 확인

사용자는 시험용 메일함 두 개를 준비했고 브라우저 로그인·인증을 직접 할 수 있다고 확인했다. 아래 네이버·구글 결과는 **사용자가 직접 본 메일·브라우저 결과**이며, A·B 계정 분리·한국어 문안·후속 앱 과업까지 검증했다는 뜻은 아니다. 메일 주소·비밀번호·링크 토큰·사연/대화 원문은 이 문서나 채팅에 적지 않는다. 계정은 A·B로만 구분한다.

| 사용자 보고 항목 | 네이버 | 구글 |
| --- | --- | --- |
| 메일 위치 | 받은편지함 | 스팸함 |
| 확인 링크·앱 로그인 연계 | 성공 | 성공 |
| 한국어 제목·본문·버튼 | 이번 보고에서 언급 없음 | 이번 보고에서 언급 없음 |

이미 가입한 주소로 가입을 다시 시도했을 때 메일은 오지 않았으나 기존 공개 화면이 발송된 것처럼 안내했다고 사용자가 보고했다. 로컬 화면은 **요청 접수·신규 가입 대상에만 메일 도착 가능**으로 고쳤다. 이는 실제 중복 판별이 아니며 새 화면은 아직 배포·브라우저 확인 전이다.

추가 [소유 확인 흐름 초안](2026-09-28-duplicate-signup-decision.md)은 기능 플래그가 꺼져 있어 공개 앱에서 아직 시험할 수 없다. 별도 시험 환경을 열면 A의 **가입 완료**, B의 **새 주소**, 별도 미완료 계정의 **가입 확인 대기**를 메일 링크 사용 후에만 구분하고, 링크 재사용·만료·타인 주소 입력만으로 상태 조회 불가를 확인한다. 새 주소는 소유 확인 메일 뒤 Supabase 가입 확인 메일이 한 통 더 오는지 실제 받은편지함/스팸함으로 확인한다. 이메일 주소·링크 원문은 기록하지 않는다.

## 지금 공개 앱에서 가능한 인증 시험

현재 공개 주소는 <https://thinkerbell-eight.vercel.app/>이다. 2026-09-28 현재 공개 앱에는 검토 브랜치의 비공개·AI 횟수·도움 평가 기능이 배포되지 않았다. 따라서 아래 인증 확인만 먼저 수행한다.

1. 서로 다른 브라우저 프로필 또는 일반 창·시크릿 창에서 A와 B를 분리한다. 두 창이 같은 로그인 세션을 공유하지 않는지 확인한다.
2. A로 신규 회원가입 → 메일 수신 위치 확인 → 한국어 제목·본문 확인 → 확인 링크 클릭 → 앱 복귀 직후 로그인 상태 확인을 한다. 비밀번호나 링크는 공유하지 않는다.
3. B도 같은 순서로 확인한다. A 창이 B 계정으로 바뀌지 않는지 확인한다.
4. 실제 만료 링크는 의도적으로 기다려 시험할 경우에만 진행한다. 받은 링크 원문을 기록하지 않고, 오류 안내·재발송·새 링크 로그인 여부만 남긴다. 인증 메일의 중복 발송을 피한다.

| 항목 | A | B | 근거·메모(개인정보 제외) |
| --- | --- | --- | --- |
| 새 가입 요청·메일 도착 | NOT_RUN | NOT_RUN | 받은편지함/스팸함만 |
| 한국어 제목·본문·버튼 | NOT_RUN | NOT_RUN | 오탈자·깨짐 여부만 |
| 확인 링크 후 앱 복귀·로그인 | NOT_RUN | NOT_RUN | 성공/오류 화면만 |
| 세션 분리 | NOT_RUN | NOT_RUN | 다른 창 상태만 |
| 만료 링크·재발송 | NOT_RUN | NOT_RUN | 선택 시험 |

## 새 DB 구조·Preview 배포 뒤에만 가능한 과업

운영 DB에는 아직 `stories.visibility`, `ai_feedback`, `ai_quota_reservations`가 없고 검토 브랜치는 공개되지 않았다. 새 SQL과 서버 경로를 시험할 수 있는 환경을 만든 뒤 A가 사연을 작성하고 B가 조회·투표·댓글·AI 방을 시험한다. A가 비공개로 바꾸면 A는 새 댓글을 **달지 못하고** 기존 댓글만 보며, B는 원문·댓글·새 방을 볼/만들 수 없어야 한다. B의 이미 소유한 AI 방은 남아야 한다. 다시 공개하면 원래 작성일과 기존 댓글·투표가 유지되어야 한다.

AI에서는 옛 방의 새 정상 저장 답변 뒤 평가, 새 방 첫 답변의 완료·저장 결과 분리, 저장 실패 후 입력 보존·새 답변 재요청, 실패 미차감, 전환 전 방 7개 무료 이어쓰기, 두 계정/두 탭의 하루 3회와 자정 경계를 구분해 기록한다. 분석 동의 전·거부 상태와 동의 후 핵심 이벤트만 GA4에 도착하는지도 QA 속성에서 확인한다. 이 단계의 결과는 현재 모두 `NOT_RUN`이다.
