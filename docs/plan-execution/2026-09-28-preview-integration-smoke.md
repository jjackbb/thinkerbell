# Preview·운영 DB 임시 계정 기술 검증 — 2026-09-28

> **시점별 근거 문서:** 아래 상태·결정·SQL 안내는 제목 날짜와 후속 기록 당시의 이력입니다. 현재 작업 지시는 [최신 인수인계](README.md)와 [PLAN](../../PLAN.md)을 따릅니다. 과거 미적용·미실행 표시만 보고 재실행하지 않습니다.


대상 앱은 Vercel Preview `dpl_4yL5BF4mnsbH9GHhSeQJSmZfKVc8`이며, DB·Auth·AI 제공자는 니편내편 운영 프로젝트 `vzhyhadjtaqbapicjrco`에 연결됐다. 실제 이용자 계정·사연·대화는 사용하지 않았다. 관리자 API로 메일 발송 없이 확인 처리된 임시 계정 A·B를 만들고, 가상 사연·댓글로 HTTP와 RLS를 확인한 뒤 생성한 데이터를 정리했다. 이는 **운영 데이터에 연결된 기술 검증**이지 일반 가입·실제 메일·브라우저 사용자 테스트가 아니다.

| 경로 | 직접 확인한 결과 |
| --- | --- |
| 인증·AI | 임시 두 계정의 비밀번호 로그인 성공. Preview의 로그인 횟수 조회는 `server`, 시작 `0/3`. A의 가상 사연 저장 후 B의 AI 방 생성 성공, 방을 열 때 차감 0. 실제 포텐스 스트림의 완료 신호와 답변·차감 원자 저장 성공 후 `1/3`. 같은 요청 ID 재시도는 저장된 답변을 돌려주고 여전히 `1/3`. 도움 평가 1건 저장 성공 |
| 참여 | 공개 사연·댓글의 비로그인 조회 성공. B의 첫 투표 A는 1건, 같은 선택 재시도에도 1건, B로 한 번 변경 후 두 번째 변경 거부. 댓글 공감은 A의 누르기·중복 누르기·취소에서 표시 수 `1→1→0` |
| 작성자 비공개 | A가 비공개로 바꾸면 A는 사연·기존 댓글을 읽고 B·비로그인 계정은 사연·댓글을 읽지 못했다. B의 기존 소유 AI 방은 계속 조회됐고 새 AI 방·비공개 사연 투표는 거부됐다. A도 비공개 중 새 댓글을 달지 못했다 |
| 재공개 | A가 공개로 되돌리면 원래 `createdAt`과 투표 수가 유지됐고 B가 원문·기존 댓글을 다시 읽었다 |
| Realtime 기술 경로 | 별도 가상 사연의 비공개 전환 시 익명 구독자에게 `story_access_invalidations` 변경이 전달됐다. 전달된 행에는 ID·사연 ID·변경 시각만 있었고 사연 본문은 없었다. 새 연결에서도 해당 무효화 ID를 조회할 수 있었지만 비공개 사연 원문은 조회되지 않았다 |
| 정리 | 임시 계정·사연·댓글·AI 방·평가·횟수·투표·공감의 삭제 요청 후 선택 조회에서 임시 이메일 패턴·가상 사연 제목·가상 댓글 내용·AI 횟수 행·평가 행이 모두 0건이었다. 이어 접근 무효화 행 1건이 남은 것을 발견해, 삭제된 가상 사연 ID·행 ID·변경 시각을 모두 대조한 조건부 삭제를 수행했다. 재조회 결과 접근 무효화 행은 0건이었다 |

별도로 현재 코드의 로컬 빌드를 모바일 크기(390×844) 헤드리스 Chrome에서 확인했다. 첫 방문에는 로그인·게스트 선택 화면이 먼저 보이고 분석 동의 배너와 GA 요청은 없었다. 게스트로 들어온 뒤 배너가 나타났다. 거부하면 GA 스크립트가 요청되지 않고 거부 상태가 새로고침 후에도 유지됐다. 별도 새 브라우저에서 동의하면 QA 측정 ID의 스크립트 로드가 시작되며 자동 페이지뷰 설정은 꺼져 있었다. 이 검사는 Google 요청을 브라우저에서 가로채 응답한 **로컬 동작 확인**이다. 실제 GA4 DebugView 수신·처리 보고서의 증거는 아니다.

요청·응답에서 비밀번호·JWT·AI 답변 본문은 기록하지 않았다. `PASS`는 이 임시 데이터와 HTTP/DB·Realtime 메시지 경로, 로컬 동의 화면에만 적용한다. 관리자 API로 확인 처리한 계정이므로 외부 메일 수신·일반 가입·비밀번호 재설정은 입증하지 않는다. 브라우저에서의 로그인 유지·핵심 과업 버튼 상태·실시간 화면 제거, 장애 주입·자정·두 탭 경합, 두 AI 모드의 실제 답변, GA4 수신과 실제 모바일 기기 동작도 별도 검증이 필요하다. 공개 Production 코드는 바꾸지 않았으며 기존 브라우저 직접 쓰기 권한은 그대로 열려 있다. 권한을 닫는 SQL 3건은 공개 앱 전환과 실제 계정 과업을 확인한 뒤 적용한다.
