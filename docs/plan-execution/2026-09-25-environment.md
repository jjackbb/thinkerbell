## 판정

**1단계 진행 중 / 다음 단계 진입 기준 미충족.** 사용자가 실제 Vercel 프로젝트의 도메인·Git 연결·Hobby 요금제를 확인했고, 당시 클라이언트 배포 파일의 일치도 확인했습니다. 니편내편 운영 DB의 구조·정책 메타데이터는 읽고 [차이를 기록](2026-09-25-supabase-schema.md)했습니다. GA4 운영·QA 속성 및 웹 스트림을 만들고 동의·첫 답변 계측 코드를 로컬에서 시험했지만, DebugView 수신·운영 배포는 확인하지 않았습니다. 로그인된 Resend 계정은 Free 요금제이며 마지막 직접 조회 당시에는 등록 도메인이 없었습니다. 사용자는 `jjackbb.com` 구매를 알렸고 공개 DNS에서 Porkbun 네임서버 위임을 확인했습니다. 후속으로 Resend가 표시한 `auth.jjackbb.com`의 DNS 레코드를 복사해 제공했고, 공개 DNS에서 DKIM·SPF·추적용 레코드 4개의 값 일치를 확인했습니다. Resend `Verified`는 사용자가 확인했습니다. 루트 DMARC `p=none`도 공개 DNS에 게시된 것을 확인했고, Supabase Auth SMTP는 꺼져 있어 실제 발송은 확인하지 못했습니다. Supabase 계정 요금제·사용량과 Vercel 배포 설정·사용량도 미확인입니다. 이후 기존 숨김 사연 1건을 삭제하고 개인 숨김 마이그레이션 2개, [계정별 댓글 공감 마이그레이션 2개](2026-09-25-comment-likes-applied.md)를 운영 DB에 적용했습니다. DB 역할 모의 시험과 실제 로그인 HTTP 시험은 구분합니다.

## 가격표 확인과 해석

- 2026-09-25에 확인한 [Resend 공식 가격표](https://resend.com/pricing)의 무료 요금은 월 3,000통·하루 100통입니다. 로그인된 계정의 Free 요금제·당시 도메인 0개를 확인했습니다. 이후 사용자가 도메인 구매와 Resend DNS 레코드 발급 화면을 알렸고 공개 DNS의 값 일치를 확인했고 사용자가 Resend `Verified`를 확인했지만 실제 발송 성공은 별개입니다.
- [Supabase 공식 가격표](https://supabase.com/pricing)와 [Vercel 공식 가격표](https://vercel.com/pricing)는 공개 요금의 참고 자료입니다. Supabase 구조 조회가 성공해도 실제 계정 요금제·현재 사용량은 별도 대시보드 확인이 필요합니다.
- [Supabase 공식 청구 안내](https://supabase.com/docs/guides/platform/billing-on-supabase)에 따르면 요금제는 프로젝트가 속한 조직 단위입니다. 니편내편 프로젝트가 속한 조직을 먼저 확인하고 그 조직의 [Usage 화면](https://supabase.com/docs/guides/troubleshooting/understanding-the-usage-summary-on-the-dashboard-D7Gnle)에서 기간·항목별 사용량을 읽어야 합니다. 유미당 계정의 조직 수치를 니편내편 수치로 옮겨 적지 않습니다.
- [Vercel 공식 Usage 안내](https://vercel.com/docs/pricing/manage-and-optimize-usage)에 따르면 팀의 Usage 화면은 기본적으로 전체 프로젝트를 합쳐 보여주며, 기간과 프로젝트 필터를 선택할 수 있습니다. 따라서 사용자 답변의 `0`을 니편내편의 모든 리소스 사용량이나 청구액 `0`으로 해석하지 않습니다.
- 사용자가 확인한 Vercel 요금제는 Hobby이며 첫 공개 목적은 무료 개인 프로젝트의 사용자 관찰·포트폴리오입니다. [Hobby 이용 조건](https://vercel.com/docs/plans/hobby)은 비상업적 개인 사용으로 제한합니다. 이 목적은 조건에 부합하는 방향이지만, 실제 운영에 결제·광고·판매 유도가 들어가지 않는지 출시 전 대조해야 합니다. 이는 계정 사용량이나 Vercel의 개별 승인 판정이 아닙니다.

## 이 단계에서 확인된 구현 차이

- 초기 조사에서 `backend/app.ts`의 Gemini 예비·모의 응답과 댓글 검사 실패 시 원문 반환 경로를 발견했습니다. 이후 [로컬 수정](2026-09-25-save-results-and-ai-provider.md)에서 이 경로를 제거하고 포텐스 단독·실패 시 오류 처리를 적용했습니다. 실제 로그인한 이용자의 공급자 완료와 서버 대화방·횟수 통제는 남아 있습니다.
- 초기 서버 파일은 AI·검사 요청 본문의 `apiKey`를 서버 키보다 우선 사용했습니다. 이후 본문 키를 무시하고 서버 키와 로그인 검증을 사용하도록 수정했습니다. 실제 공급자 호출은 확인하지 않았습니다.
- `frontend/src/lib/ga4.ts`와 `frontend/src/main.tsx`의 동의 전 자동 로드 문제는 수정했습니다. 아직 운영 측정 ID를 설정하지 않았고, 모든 명세 이벤트·공급자 완료·저장 복원은 확인되지 않았습니다. ID 설정만으로 공개 계측 완료라고 판단하지 않습니다.
- 사연·댓글 저장 성공 표시가 실제 서버 결과와 어긋나던 위치를 확인했고, 이후 [로컬 코드에서 저장 응답 뒤 갱신](2026-09-25-save-results-and-ai-provider.md)하도록 수정했습니다. 실제 로그인 계정의 원격 실패·재시도는 NOT_RUN입니다.
- `frontend/src/components/PremiumModal.tsx`의 ‘구독 알아보기’는 현재 닫기 동작만 합니다. 무료 개인 프로젝트라는 사용자 선택과 PLAN의 구독 ‘준비 중’ 표시에 맞게, 첫 공개 전 문구·동작을 실제 상태와 일치시켜야 합니다. 이번 단계에서 수정하거나 공개 동작을 시험하지 않았습니다.
- 운영 DB의 `stories`·`comments`는 익명 조회 권한과 조건 `true`인 RLS 조회 정책을 가집니다. PLAN의 작성자 비공개·성인 차단은 현재 DB 권한으로 보장되지 않습니다. 초기 조사 당시 `isHidden=true`였던 1건은 사용자 요청으로 삭제했고 사용자별 숨김 관계를 [별도 테이블로 적용](2026-09-25-story-hides-applied.md)했습니다. 작성자 비공개 권한은 아직 없습니다.

이 차이는 **코드 확인으로 얻은 작업 대상**이며, 사용자가 직접 결함을 재현했거나 제품 개선을 달성했다는 증거가 아닙니다.

## 포트폴리오용 전달 포인트

사용자는 최신 PLAN으로 환경 확인부터 시작하고, 불확실한 방향·의도·충돌은 임의 처리하지 말고 마지막에 한꺼번에 질문하라고 요청했습니다. 개인 숨김·작성자 비공개와 계정별 댓글 공감·취소 규칙을 확정했습니다. 공개 주소와 Vercel 프로젝트의 도메인·Git 연결·Hobby 요금제, 무료 개인 프로젝트라는 첫 공개 목적, 두 Supabase 계정의 구분도 확인했습니다. 사용자가 GA4 별도 계정·참여/유지 목적을 선택하고 약관에 직접 동의한 뒤 AI가 계정·속성·웹 스트림을 생성·확인했습니다. AI가 수행한 나머지 작업은 연결 대상 대조, 공식 요금표 확인, 공개 프론트 파일 비교, 운영 DB **구조 메타데이터**와 로컬 SQL 비교, 코드 정적 점검입니다. 사용자 결정·확인과 AI의 조회 결과를 혼합하거나 사용자가 직접 구현·검증한 성과로 바꾸지 않습니다. 포트폴리오에서 현재 사용할 수 있는 표현은 **“공개 전 운영 구조와 계획의 차이를 확인하고 GA4 수집 기반을 구성했으며, 실제 수집·역할별 시험의 검증 조건을 분리했다”**까지입니다. 실제 가입 완주·AI 도움·GA4 개선·역할별 DB 안전성은 주장할 수 없습니다.
