# 저장 결과 표시와 AI 공급자 경계 후속

2026-09-25 [PLAN.md](../../PLAN.md) §2의 저장·등록 결과와 포텐스 단독 규칙을 로컬 코드에 반영했다. 이 문서의 코드는 아직 Vercel에 배포하지 않았고, 실제 로그인 계정으로 저장 과업을 끝까지 시험하지 않았다.

## 로컬 동작 변경

| 경로 | 변경한 기준 |
|---|---|
| 댓글 등록 | `/api/comments`가 로그인·사연 상태를 확인하고 서버 포텐스로 검사한 본문을 저장한다. INSERT 응답 뒤에만 입력을 지운다. 전송 중 중복 클릭을 막고 같은 초안의 재시도에는 같은 댓글 ID를 사용한다. 기존 ID면 본인·사연이 맞는 저장 행을 재사용한다. DB 트리거가 확정한 익명 표기를 화면에 반영한다. |
| 댓글 수정·삭제 | 수정은 `/api/comments/:id`에서 본인·사연·포텐스 재검사를 거쳐 반환 행을 확인한 뒤 화면을 갱신한다. 삭제는 기존 본인 조건의 DB 응답 뒤 화면을 갱신한다. 실패한 수정 입력은 유지한다. |
| 사연 삭제 | 본인 ID 조건의 DELETE가 삭제 행을 반환한 뒤 목록에서 제거한다. 실패하면 확인창을 유지하고 재시도할 수 있다. |
| 닉네임 | 랜덤 생성은 편집 칸만 채운다. `supabase.auth.updateUser` 성공 뒤 프로필 이름을 바꾸고, 실패하면 입력을 유지한다. |
| 신고 | `submit_report` RPC 성공과 결과 형식을 확인한 뒤 접수 화면을 표시한다. 실패하면 사유를 유지하고 다시 제출할 수 있다. |
| 댓글 검사 | 서버가 이용자 토큰을 확인하고 **서버의 포텐스 키만** 사용한다. 공급자 실패·빈 응답·키 없음은 오류이며 원문을 검사 성공으로 반환하지 않는다. |
| AI API | `/api/chat`와 `/api/chat-stream`이 이용자 토큰과 `ai_personas`의 대화방 소유자를 확인하고 서버에 저장된 지시문·최근 대화 기록을 읽는다. 브라우저가 보낸 키·모델·지시문·기록, Gemini 대체 응답, 키 없는 모의 응답을 사용하지 않는다. 공급자 장애는 오류로 전달한다. |

## 확인한 범위

- `npm run lint`, `npm run build`, `git diff --check` 통과. 빌드 시 기존 500 kB 초과 클라이언트 청크 경고는 남았다.
- 빌드된 로컬 서버의 `/api/chat`, `/api/chat-stream`, `/api/sanitize-text`에 인증 없이 요청하자 모두 HTTP 401 `AUTH_REQUIRED`였다. 요청 본문의 `apiKey` 값은 공급자 키로 사용되지 않는다.
- 후속 댓글 변경 후 재빌드한 로컬 서버에서 `/api/comments` POST와 `/api/comments/:id` PUT의 비로그인 요청은 각각 HTTP 401 `AUTH_REQUIRED`였다. 이 검사는 인증 뒤 포텐스 검사나 DB 저장 성공을 확인하지 않는다.
- 실제 이용자 토큰을 사용한 포텐스 응답·댓글 저장·닉네임 변경·신고 접수, 화면의 실패/재시도, Vercel 배포는 **NOT_RUN**이다. DB 역할 모의 시험과 개인 숨김 DB 적용은 [별도 결과](2026-09-25-story-hides-applied.md)다.

## 아직 남은 경계

- 사연·댓글의 직접 Supabase INSERT/UPDATE 정책은 유지된다. 따라서 댓글 검사와 사연 검사 API를 거치지 않는 직접 요청을 아직 막지 못한다. [사연 정책 초안](sql/story-write-boundary.sql)은 서버 인증 저장 배포·시험 뒤 적용한다.
- 댓글 등록·수정은 서버 검사 경로를 사용하도록 로컬 코드를 고쳤다. 하지만 운영 DB의 직접 INSERT/UPDATE 정책이 살아 있어 브라우저에서 직접 Supabase로 쓰면 이 검사를 우회할 수 있다. 서버 경로를 실제 계정에서 확인한 뒤 [댓글 정책 변경 초안](sql/comment-write-boundary.sql)을 적용해야 한다. 비공개 전환과 댓글 등록이 경합할 때의 DB 잠금·검사는 [접근 경계 점검](2026-09-25-author-private-boundary.md)에서 별도로 다룬다.
- AI API의 대화방 소유권·저장 지시문 조회 코드는 로컬에 추가했으나, 실제 계정/공급자 시험은 `NOT_RUN`이다. 현재 `ai_personas`의 본인 직접 INSERT/UPDATE 정책은 살아 있어 본인이 대화방 내용을 직접 바꿀 수 있으며, 새 방 생성의 사연 공개 권한과 하루 3회 예약/차감·중복/동시 요청 제한도 아직 서버에서 강제하지 않는다. 따라서 **AI 권한·비용 통제 완료**로 표현하거나 이 상태로 공개하면 안 된다.
