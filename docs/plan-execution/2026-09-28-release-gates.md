## 다음 실행 순서

1. **결정과 시험 자료 확정.** 작성자도 비공개 사연에 새 댓글을 달지 못한다. 옛 AI 방은 새 정상 저장 답변 뒤 평가하되, 모드 정보가 없는 옛 방 2개의 평가는 제외한다. 대화는 첫 공개에서 자동 삭제하지 않는다. 도움 평가는 월·두 모드 합계·최소 5명으로 정했다. 개인 행은 최대 30일, 월말에도 서로 다른 평가자 5명을 증명할 수 없으면 임시 합계를 폐기한다. 가입 중복은 메일함 소유 확인 후에만 알려주며 신규 가입 메일은 한 통, 발송 상한·보관·별도 키·비밀번호 재설정도 확정했다. 사용자가 보고한 네이버·구글 수신·로그인 성공은 별도로 보존하고 A·B 분리·앱 과업은 추가 검증한다. 비밀번호·메일 원문·토큰은 문서에 남기지 않는다.
2. **운영 구조 차이 재확인.** 적용 직전 테이블/정책/함수·기존 AI 방 7개의 구조 집계·고유 인덱스 충돌만 다시 읽는다. 실제 사연·대화 본문을 시험 자료로 읽지 않는다. 격리 DB의 댓글 생성↔비공개 전환 경합과 AI 방 생성 경합을 시험한다. 초안이 운영 구조와 다르면 적용을 중단한다.
3. **호환 DB 변경과 미공개 검증.** 새 테이블·함수·트리거·읽기 권한과 투표 함수를 순서대로 검토해 적용한다. `sql/story-author-private-draft.sql`은 비공개 중 작성자를 포함한 새 댓글을 DB에서 차단하도록 보완했고 격리 DB 시험을 다시 한다. `sql/ai-feedback-draft.sql`에서는 미승인 일별 소수 표본 집계를 제거하고 보수적인 월 합계·30일 이내 개인 행 삭제를 격리 DB에서 시험했다. 운영 구조 대조·적용 순서·실제 계정 시험 전에는 도움 평가 SQL을 운영에 적용하지 않는다. 적용한 마이그레이션 버전과 결과를 별도 기록한다.
4. **서버·화면을 비활성 상태로 올려 시험.** 검토된 Vercel 프로젝트 `thinkerbell`의 Preview와 Production 설정 차이를 확인한다. 새 앱은 `AI_QUOTA_ACTIVATES_AT`이 없으면 배포 환경의 AI API가 503으로 닫힌다. 준비된 배포일 이후 다음 한국 시간 0시를 정확한 ISO 시각으로 설정하고, SQL·서버 역할 시험 전에는 `AI_QUOTA_SERVER_READY=true`를 설정하지 않는다. 작성자 비공개 버튼은 빌드 환경의 `VITE_AUTHOR_PRIVATE_ENABLED=true`와 DB 열 검사가 모두 충족될 때만 노출된다. 비밀값은 채팅·문서·Git에 기록하지 않는다.
5. **두 실제 시험 계정으로 검증.** [브라우저 확인표](2026-09-28-two-account-browser-checklist.md)에 따라 가입 확인·재발송·만료 링크·앱 복귀, 공개/개인 숨김/작성자 비공개/재공개, REST 직접 접근·Realtime 연결 끊김 복구, 투표·댓글·공감, 기존 AI 방 무료 이어쓰기, 첫 답변 저장/차감·실패 반환·자정·동시 요청, 평가 저장/건너뛰기/삭제, AI 오류 신고의 운영자 목록을 확인한다. 각 결과를 `PASS/FAIL/NOT_RUN/BLOCKED`로 적는다. 데이터 노출·손실 또는 저장 장애가 나오면 다음 단계로 넘어가지 않는다.
6. **직접 쓰기 권한을 마지막에 닫는다.** 검증된 서버 경로가 동작한 뒤 `story-write-boundary.sql`, `comment-write-boundary.sql`, `ai-direct-write-boundary-draft.sql`의 적용 결과를 확인한다. 기존 공개 앱이 브라우저 직접 쓰기에 의존하므로 서버 배포와 권한 변경 사이의 호환 시각을 기록한다. 활성화 시각 전후의 실제 사용 기록을 소급 변환하지 않는다.
7. **공개와 관찰.** Production 버전/시간·환경변수 이름·DB 마이그레이션 버전을 대조하고 공개 URL에서 과업을 완주한다. GA4 시험용·운영용 ID를 분리해 동의 후 DebugView, 이어 처리 보고서를 대조한다. 직접 모집과 공개 후 관찰을 병행하고, 첫 개선은 실제 실패·이탈·인터뷰 근거가 모인 뒤 선택한다.

## 되돌림과 남은 위험

- 기존 7개 AI 방은 무료 이어쓰기다. 임의 삭제·재차감하지 않는다.
- 옛 방의 기존 말풍선만으로는 도움 평가를 열지 않는다. 모드가 알려진 방에는 새 정상 저장 답변이 필요하고, 모드 정보가 없는 옛 방 2개에는 평가를 열거나 저장하지 않는다. 방과 대화는 유지한다. 첫 공개에는 대화 자동 삭제가 없으며 본인 삭제·탈퇴 삭제만 있다.
- 새 AI 저장·차감은 원자 거래 초안이지만 운영 REST/브라우저 검증 전이다. 저장 실패 시 차감하지 않고 입력을 남겨 새 답변을 요청한다.
- 실시간 ID 무효화는 로컬 코드·격리 DB 수준이다. 다른 계정 브라우저가 이미 본 원문을 즉시 지우는지는 실제 Realtime 시험이 필요하다.
- 버튼 정적 선언 [167곳](2026-09-28-button-inventory.md)은 위치 목록이다. 안정적인 ID·결과 이벤트·실제 노출 검증과 GA4 수신은 완료하지 않았다.
- GA4 외부 전송은 핵심 과업의 진입·선택·저장 결과로 제한했다. 로그인·앱 열기·화면 이동의 GA4 전송은 제거했으며 신고·위기 지원·계정 행동의 이벤트도 추가하지 않는다. 운영 수신 시험은 남아 있다.
- 대화 내용·가입 메일·실제 사용자 가치에 관한 판정은 로컬 빌드나 SQL 역할 시험으로 대체하지 않는다.
