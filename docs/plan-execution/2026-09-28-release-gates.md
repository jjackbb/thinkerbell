[PLAN.md](../../PLAN.md)가 정책 기준이다. 이 문서는 현재 코드·DB·배포가 서로 다른 단계에 있다는 사실과 다음 실행 순서를 팀에 전달한다. 가입 소유 확인 SQL 2건에 이어 투표·작성자 비공개·AI·평가 관련 호환 마이그레이션 9건도 [운영 DB에 적용](2026-09-28-db-expansion-applied.md)했다. 새 앱은 Preview에만 배포했고 Production 공개 앱은 이전 버전이다. 기존 브라우저 직접 쓰기는 열려 있으며 차단 SQL 3건은 미적용이다.

## 다음 실행 순서

1. **결정과 시험 자료 확정.** 작성자도 비공개 사연에 새 댓글을 달지 못한다. 옛 AI 방은 새 정상 저장 답변 뒤 평가하되, 모드 정보가 없는 옛 방 2개의 평가는 제외한다. 대화는 첫 공개에서 자동 삭제하지 않는다. 도움 평가는 월·두 모드 합계·최소 5명으로 정했다. 개인 행은 최대 30일, 월말에도 서로 다른 평가자 5명을 증명할 수 없으면 임시 합계를 폐기한다. 가입 중복은 메일함 소유 확인 후에만 알려주며 신규 가입 메일은 한 통, 발송 상한·보관·별도 키·비밀번호 재설정도 확정했다. 사용자가 보고한 네이버·구글 수신·로그인 성공은 별도로 보존하고 A·B 분리·앱 과업은 추가 검증한다. 비밀번호·메일 원문·토큰은 문서에 남기지 않는다.
2. **운영 구조 차이 재확인 — 완료.** 적용 직전 본문 없이 테이블/정책/함수·AI 방 5개·중복 그룹 0개를 조회했다. 과거 7개 집계와의 차이는 원인 미확인으로 남긴다. 격리 DB의 댓글 생성↔비공개 전환 경합과 AI 방 생성 경합은 통과했다.
3. **호환 DB 변경 — 완료, 실제 계정 시험 대기.** 새 테이블·함수·트리거·조회 정책·투표 함수·정리 작업을 순서대로 적용하고 [마이그레이션 버전과 결과](2026-09-28-db-expansion-applied.md)를 기록했다. 격리 DB 계약은 통과했으나 도움 평가와 비공개를 실제 계정으로 사용한 운영 시험은 남았다.
4. **서버·화면 Preview 시험 진행 중.** Vercel `thinkerbell`의 Preview에 QA GA4 ID, 작성자 비공개 화면 플래그, 가입 소유 확인용 서버 비밀값·발송 키와 양쪽 플래그를 설정했다. Preview는 배포마다 새 URL을 받아 메일 링크도 해당 배포 URL을 사용하며, URL이 없으면 발송을 막는다. 사용자가 오늘 시험을 선택해 Preview에만 `AI_QUOTA_ACTIVATES_AT=2026-09-28T00:00:00+09:00`, `AI_QUOTA_SERVER_READY=true`를 추가하고 새 배포를 만들었다. Production 변수 목록에 이 두 이름이 없는 것도 확인했다. 이는 기존의 '준비된 배포 뒤 다음 자정' 전환 규칙을 **시험 배포에 한해서** 앞당긴 것이며, 운영 전환 시각은 별도로 정해야 한다. 이전 Preview의 임시 계정 실제 포텐스 답변·저장·차감과 권한 HTTP/DB는 [기술 검증](2026-09-28-preview-integration-smoke.md)을 통과했다. 17:49 Preview에서 임시 계정의 계정 전환·실시간 원문 제거, 주입 500 실패 화면과 QA 가상 `story_view` 수집 요청까지 [브라우저로 확인](2026-09-28-preview-browser-followup.md)했다. 일반 가입·외부 메일·실제 이용자의 브라우저 과업은 미확인이다. 비밀값은 채팅·문서·Git에 기록하지 않는다.
5. **두 실제 시험 계정으로 검증.** [브라우저 확인표](2026-09-28-two-account-browser-checklist.md)에 따라 가입 확인·재발송·만료 링크·앱 복귀, 공개/개인 숨김/작성자 비공개/재공개, REST 직접 접근·Realtime 연결 끊김 복구, 투표·댓글·공감, 기존 AI 방 무료 이어쓰기, 첫 답변 저장/차감·실패 반환·자정·동시 요청, 평가 저장/건너뛰기/삭제, AI 오류 신고의 운영자 목록을 확인한다. 각 결과를 `PASS/FAIL/NOT_RUN/BLOCKED`로 적는다. 데이터 노출·손실 또는 저장 장애가 나오면 다음 단계로 넘어가지 않는다.
6. **직접 쓰기 권한을 마지막에 닫는다.** 검증된 서버 경로가 동작한 뒤 `story-write-boundary.sql`, `comment-write-boundary.sql`, `ai-direct-write-boundary-draft.sql`의 적용 결과를 확인한다. 기존 공개 앱이 브라우저 직접 쓰기에 의존하므로 서버 배포와 권한 변경 사이의 호환 시각을 기록한다. 활성화 시각 전후의 실제 사용 기록을 소급 변환하지 않는다.
7. **공개와 관찰.** Production 버전/시간·환경변수 이름·DB 마이그레이션 버전을 대조하고 공개 URL에서 과업을 완주한다. GA4 시험용·운영용 ID를 분리해 동의 후 DebugView, 이어 처리 보고서를 대조한다. 직접 모집과 공개 후 관찰을 병행하고, 첫 개선은 실제 실패·이탈·인터뷰 근거가 모인 뒤 선택한다.

## 되돌림과 남은 위험

- 비밀번호 재설정의 Supabase Auth 설정은 사용자가 운영 URL과 Preview 패턴, 한국어 템플릿을 선택했다. 사용자가 니편내편 계정의 임시 전체 권한 관리 토큰을 로컬에 둔 뒤 [설정 도구](../../tools/configure-auth-recovery.mjs)로 현재 프로젝트 ref·Site URL을 확인하고, 기존 허용 URL을 보존하며 승인된 URL 2개와 한국어 Reset Password 제목·본문만 적용했다. Management API 재조회가 일치했고 토큰은 로컬 `.env`에서 제거했다. 실제 재설정 메일의 도착·복귀·비밀번호 저장·재로그인은 아직 확인하지 않았다. 전체 권한 토큰은 Supabase 계정의 [Access Tokens](https://supabase.com/dashboard/account/tokens)에서 별도로 회수해야 한다.

- 전환 전 방은 모두 무료 이어쓰기다. 과거 집계는 7개, 적용 직전 집계는 5개였으며 감소 원인은 확인하지 않았다. 임의 삭제·재차감하지 않는다.
- 옛 방의 기존 말풍선만으로는 도움 평가를 열지 않는다. 모드가 알려진 방에는 새 정상 저장 답변이 필요하고, 모드 정보가 없는 옛 방 2개에는 평가를 열거나 저장하지 않는다. 방과 대화는 유지한다. 첫 공개에는 대화 자동 삭제가 없으며 본인 삭제·탈퇴 삭제만 있다.
- 새 AI 저장·차감은 임시 계정의 Preview HTTP와 운영 DB에서 정상 완료·같은 요청 재시도까지 통과했다. Preview 브라우저의 **주입된** 저장 실패는 입력·미저장 답변 보존·차감 0으로 복구됐고, 뒤이은 실제 포텐스 새 답변은 저장·1회 차감됐다. 운영 DB 함수의 마지막 1회 동시 요청·자정 요청일 귀속도 가상 데이터로 통과했다. 실제 공급자·DB 장애와 실제 계정 브라우저 과업은 미검증이다.
- 실시간 ID 무효화 메시지는 운영 DB 구독에서 전달됐고 [로컬 Chrome의 B 계정 화면](2026-09-28-pretest-browser-boundaries.md)에서 이미 본 원문·URL 제거를 확인했다. 첫 구독 전환 시도는 실패했으므로 구독 교체 순간의 경합 가능성은 남는다. [17:49 Preview의 임시 계정 브라우저](2026-09-28-preview-browser-followup.md)에서는 전환 후 화면·URL 제거가 통과했다. 실제 메일 계정·구독 교체 순간의 결과는 미확인이다.
- 버튼 정적 선언 [174곳](2026-09-28-button-inventory.md)에 고유한 ID를 부여하고 [화면별 계약 지도](2026-09-28-button-behavior-matrix.md)에 전부 배치해 누락·중복 0개를 확인했다. 조건부 실제 노출·서버 결과와 GA4 수신은 완료하지 않았다.
- 첫 공개에서 준비 중인 알림의 켜기/끄기 버튼 3개를 제거했다. 이의 제기는 서버 실패 때 입력창을 유지하고, AI 대화 전체 삭제는 서버 성공 뒤에만 확인창을 닫도록 바꿨다. [17:49 Preview 브라우저](2026-09-28-preview-browser-followup.md)에서 이의 제기·전체 삭제에 주입한 500 뒤 입력·확인 화면 보존을 확인했고, 18:47 Preview에서 같은 화면의 정상 재시도 저장·삭제까지 확인했다. 사용자는 이 범위를 공개 전 복구 기준으로 인정했다. 실제 서버 장애는 재현하지 않았으며 운영에서 발생하면 별도 기록한다.
- GA4 외부 전송은 핵심 과업의 진입·선택·저장 결과로 제한했다. 로그인·앱 열기·화면 이동의 GA4 전송은 제거했으며 신고·위기 지원·계정 행동의 이벤트도 추가하지 않는다. 운영 수신 시험은 남아 있다.
- 대화 내용·가입 메일·실제 사용자 가치에 관한 판정은 로컬 빌드나 SQL 역할 시험으로 대체하지 않는다.
