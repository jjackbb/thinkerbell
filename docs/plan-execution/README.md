3. **QA AI 이벤트:** 선택적 분석 동의 뒤 `ai_chat_turn1`과 저장 결과 이벤트를 실제 과업에서 발생시키고 QA 화면 수신을 확인한다. 답변 완료와 저장 성공은 별개다. 합성 probe의 수신을 AI 과업 성공으로 대체하지 않는다.
4. **남은 공개 조건:** 조건부 버튼·신고/성인 보류 경계·실기기·정리 cron 첫 실행 등 근거 문서의 미완료 항목을 확인한다. 9월 28일 첫 cron 실행이 없었다는 기록은 현재 조회가 아니므로 필요 시 읽기 재확인한다.
5. **Production 준비와 전환:** [첫 공개 전환 인수인계](2026-09-28-release-gates.md)의 순서와 중단 조건을 따른다. 마지막 점검 시 Production에는 새 AI/가입/비공개/GA4 플래그와 가입 발송 설정 일부가 없었다. 실제 필요 변수는 코드와 대조한다. 준비된 배포 뒤 다음 한국 시간 0시부터 AI 횟수를 켜는 정책은 확정됐지만 구체적인 운영 시각은 미확정이다. Preview의 `2026-09-28T00:00:00+09:00`은 과거 시험값이며 운영에 복사하거나 “오늘”로 설명하지 않는다.
6. **새 Production 서버 경로 검증 뒤 직접 쓰기 차단:** 기존 공개 앱은 직접 쓰기에 의존하므로 차단 SQL을 먼저 적용하면 안 된다. 사연·댓글·AI 정책 7개를 준비 SQL과 대조한다. `draft` 이름만 보고 미적용이라고 판단하지 말고 호환 확장 9건의 적용 이력과 별도 차단 SQL을 구분한다.

## PLAN 출시 단계 진행률

2026-09-28 현재 [PLAN의 7단계 완료 조건](../../PLAN.md)을 모두 만족한 단계는 **0/7**이다. 기능을 몇 개 만들었는지를 백분율로 환산한 수치가 아니다. 1단계 환경은 기존 Vercel·Supabase·GA4·인증 SMTP와 Auth 재설정 URL·문안 적용값을 확인했지만 실제 재설정 메일·운영 메일 시험은 남았다. 2단계 구현은 로컬 코드·SQL 초안이 많지만 전체 버튼 계약이 미완료다. 3단계 시험은 격리 시험과 임시 계정 Preview HTTP/DB·로컬 브라우저 일부 시나리오가 통과했지만 전체 시나리오는 미완료다. 4단계 운영 전환은 개인 숨김·댓글 공감·가입 소유 확인·투표·비공개·AI·평가의 호환 DB 변경까지 적용했으나 앱 배포와 직접 쓰기 차단은 남았다. 5단계 실제 연동은 사용자의 가입 메일·로그인 관찰 및 임시 계정의 포텐스 답변·저장 기술 검증이 있다. 6단계 공개·모집과 7단계 보고서 대조·개선 판정은 아직 시작하지 않았다. **`0/7`은 출시 게이트의 완료 수**이며 작업량이 0이라는 뜻은 아니다.

## 사용자가 결정하거나 직접 한 일

- 무료 개인 프로젝트의 첫 공개를 사용자 관찰·포트폴리오 목적으로 정했다. 월 비용 상한은 10만 원이다.
- 개인 숨김은 숨긴 사람에게만 적용하고, 작성자 비공개는 모든 다른 사람에게 숨긴다. 작성자 비공개는 마이페이지 '작성한 사연'에서 구분하고, 재공개해도 원래 작성일을 유지한다.
- 기존 의미 불명의 `isHidden=true` 사연 1건은 연결 기록을 다시 확인한 뒤 삭제하도록 요청했다. 댓글 공감은 계정당 1회·재클릭 취소로 정하고, 과거 계정별 근거가 없는 표시 숫자는 0으로 재설정하기로 했다.
- GA4는 선택적 동의 후 측정하고, 첫 정상 AI 답변과 대화 저장 결과를 따로 기록하기로 했다. 운영·시험 속성을 분리하고 첫 방문 로그인·게스트 선택 뒤에 동의 배너를 보여주기로 했다.
- `jjackbb.com`을 구매했다고 알리고 Resend `auth.jjackbb.com`을 연결했다. 도메인 `Verified`, Enforced TLS, 열람·클릭 추적 끄기, Supabase Site URL과 Custom SMTP 저장은 사용자의 대시보드 확인이다. 기존 Auth 계정은 그대로 두고 **새 가입부터** 이메일 확인을 적용하기로 했다.
- 사용자는 `Confirm Email`을 켜고 새 가입→네이버 받은편지함 수신→앱 복귀 후 로그인 상태까지 시험했다. 니편내편 Auth 집계는 기존 45명에서 46명으로 늘었고 새 계정 1명의 확인 시각이 기록됐다. 받은 메일은 영어였고, 이후 사용자가 [한국어 제목·본문](2026-09-26-auth-email-korean-draft.md)으로 직접 수정했다고 알렸다. 저장 완료와 역슬래시 없는 HTML 입력은 사용자가 확인했다. 수정 후 새 메일 수신은 아직 확인하지 않았다. [후속 검증 기록](2026-09-26-auth-email-verified.md)은 사용자 관찰과 DB 확인 범위를 구분한다.
- AI 횟수 제한의 운영 검증에는 **사용자가 관리하는 새 전용 이메일 계정 두 개**를 쓰고 사용자가 브라우저 로그인·메일 인증을 직접 하기로 했다. 사용자는 메일함 두 개의 준비·브라우저 인증 가능을 확인했다. 이후 네이버 받은편지함·구글 스팸함 수신과 각각 확인 링크 후 로그인 성공을 보고했다. [두 계정 확인표](2026-09-28-two-account-browser-checklist.md)의 A·B 계정 분리와 새 기능 과업은 아직 미확인이다. 하루 3회의 날짜는 첫 실제 AI 요청을 서버가 받은 **한국 날짜**, 횟수 처리 기록은 **종료 후 30일 보관**으로 확정했다.
- [5개 결정 기록](2026-09-28-open-decisions.html): 전환 전 기존 방 7개 모두 무료 이어쓰기, 저장 실패 미차감·입력 보존 후 새 답변 요청, 개인 숨김 사연의 기존 소유 AI 대화 이용 유지, 두 AI 모드의 정상 답변 후 마무리 평가, 새 메일함 2개는 사용자가 준비·인증한다.
- [후속 결정 6개](2026-09-28-next-decisions.html): 비공개 중 작성자도 새 댓글을 달지 못함, 옛 방의 새 정상 저장 답변 뒤 평가, 첫 공개의 대화 자동 삭제 없음, 월 전체 모드 합계의 최소 5명 조건, GA4 핵심 과업·저장 결과만 전송, 메일함 두 개 준비를 사용자가 확정했다. 추가로 모드가 없는 옛 방 2개 평가 제외, 월말에도 5명을 증명할 수 없으면 임시 집계 폐기, 개인 평가 최대 30일 보관을 확정했다.
- [기존 이메일 재가입](2026-09-28-duplicate-signup-decision.md)은 사용자 선택에 따라 **메일함 소유 확인 후에만 가입 상태 안내**로 정했다. 신규 가입은 메일 한 통, 발송은 주소당 시간당 3회·전체 하루 50회, 링크 10분·기록 약 24시간, 별도 Resend 발송 키, 기존 계정의 비밀번호 재설정 경로를 확정했다. 사용자 후속 요청으로 쓰기 MCP에서 [가입 소유 확인 SQL 2건을 운영 DB에 적용하고 권한·작업 등록을 조회](2026-09-28-signup-email-ownership-applied.md)했다. 정리 작업은 조회 시점 38회, 최신 실행 성공이다. 사용자는 A·B 가입 링크 시험 완료를 보고했으나 개별 결과를 아직 제공하지 않았다. 기능 플래그는 Preview만 켜고 Production은 꺼져 있다.

**작업 중·작업 전 이어가기:** [조건부 핵심 버튼·AI 실패 재요청/복원·Production 읽기 전용 사전 점검](2026-09-28-in-progress-release-preflight.md)을 추가했다. 임시 계정의 실제 저장 성공과 주입 오류를 분리했고, 공개 배포·직접 쓰기 차단은 실행하지 않았다.

운영 DB에 적용한 SQL과 로컬 앱 변경은 별개다. **운영 적용된 마이그레이션이 있다고 새 화면까지 배포됐다고 주장하지 않는다.** 현재 GitHub `main`·Vercel 운영 배포에 반영된 새 기능 코드는 인증 화면뿐이다. 검토용 브랜치의 미완료 코드는 기능별로 검증한 뒤 단계적으로 배포한다. 브라우저 시험과 외부 서비스 응답은 로컬 타입 검사·빌드로 대체하지 않는다.

니편내편 Supabase MCP에서 개인 숨김·댓글 공감·가입 소유 확인 마이그레이션 6건과 [후속 호환 확장 9건](2026-09-28-db-expansion-applied.md)의 적용을 확인했다. 저장소 `backend/supabase/migrations/`의 대응 파일이 적용 이력이다. `sql/`의 이름에 `draft`가 남은 일부 파일은 검토 당시 원본이므로 같은 SQL을 다시 실행하지 않는다. 아직 미적용인 직접 쓰기 차단은 `sql/story-write-boundary.sql`, `sql/comment-write-boundary.sql`, `sql/ai-direct-write-boundary-draft.sql` 3건이다. 새 서버 앱 배포·실제 계정 검증 뒤에만 적용한다.

사용자 결정·설정 작업과 AI가 수행한 코드 수정·조회·검사를 섞어 개인 기여로 기록하지 않는다. 포트폴리오 원천 자료는 사용자가 지정한 개인비서의 니편내편 폴더에 별도로 보존한다.

AI 전환과 마무리 UX의 5개 질문은 [결정 기록](2026-09-28-open-decisions.html)에 답변 완료 상태로 보존했다. 두 메일함의 준비는 사용자가 추가로 확인했지만 운영 DB 변경·배포·실사용 검증 완료를 뜻하지 않는다.
