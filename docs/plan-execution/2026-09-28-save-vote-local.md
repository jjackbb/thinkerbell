# 사연 재시도·투표 결과 로컬 보완 — 2026-09-28

최신 기능 기준은 [PLAN](../../PLAN.md)이다. 이번 작업은 저장·참여 기능의 성공 표시와 중복 방지에 관한 **로컬 구현**이며, 운영 DB·Vercel에는 아직 적용하지 않았다.

## 변경한 동작

| 경로 | 이전 문제 | 지금 로컬 코드 |
| --- | --- | --- |
| 투표 | 카드·상세 화면이 DB 응답 전 선택을 표시하고, 앱이 투표 수를 추측해 증감했다. 실패한 클릭이 잠시 성공처럼 보이고 연타가 겹칠 수 있었다. | `vote_story` RPC의 성공과 반환 사연을 확인한 뒤 선택·숫자를 갱신한다. 요청 중 같은 사연의 재클릭을 막는다. 응답을 못 받으면 성공 이벤트를 보내지 않고 가능한 범위에서 사연·내 투표 기록을 다시 읽는다. |
| 사연 신규 등록 | 서버가 매번 새 ID를 만들어, 저장 후 응답만 끊기면 재시도 때 동일 사연이 또 생길 수 있었다. | 작성 모달을 연 동안 `story-UUID` 요청 ID 하나를 유지한다. 서버는 같은 ID의 본인 사연이 이미 있으면 기존 행을 반환하고, 동시 INSERT 충돌도 같은 방식으로 복구한다. 타인 행과 ID가 겹치면 내용을 공개하지 않고 거부한다. 복구한 행의 내용이 현재 입력과 다를 수 있어 화면에 확인 안내를 보여준다. |

이 중복 방지는 **같은 작성 모달에서 재시도한 요청**에 적용된다. 새로고침 뒤 입력을 다시 작성한 시도까지 동일 사연으로 식별하는 기능은 아니다. 수정 기능의 소유권 검사는 기존 로컬 경로를 유지한다.

## 확인한 범위

- `npm run lint`, `npm run build`, `git diff --check` 통과. 빌드에는 기존 500 kB 초과 클라이언트 청크 경고가 남는다.
- 로컬 HTTP에서 모의 Supabase·포텐스 응답만 사용한 `npm run test:story-save`: 최초 저장→같은 ID 재시도 시 INSERT·검사 추가 호출 없음, 잘못된 ID 거부, 동시 INSERT 충돌 복구 **3건 PASS**. 첫 샌드박스 실행은 `listen EPERM`이었고, 허용된 로컬 127.0.0.1 시험에서 재실행해 통과했다.
- 실제 로그인 브라우저의 투표 첫 선택·변경·실패, 사연 저장·응답 손실, 운영 DB·포텐스 요청은 **NOT_RUN**이다. 모의 응답 시험을 실서비스 통과로 읽지 않는다.
- 니편내편 읽기 전용 Supabase MCP를 재인증한 뒤 운영 `public.vote_story(p_story_id text, p_option text)`의 반환형이 `stories`임을 확인했다. 이 조회는 **함수의 형태만** 확인한 것으로, 운영 투표 동작·권한·브라우저 표시 시험은 아니다.

## 투표 함수 후속 초안

운영 함수 정의를 다시 읽어, 같은 선택의 RPC 재요청이 아직 오류를 반환하고 최초 동시 투표 때는 **존재하지 않는 투표 행을 잠그지 못한다**는 점을 확인했다. 운영 함수에는 `anon`의 직접 `EXECUTE` 권한도 남아 있다. 이에 [적용 전 SQL](sql/vote-story-idempotent.sql)을 작성했다. 사연 행을 먼저 잠그고, 같은 선택은 숫자·변경 횟수 수정 없이 현재 행을 반환하며, 첫 변경 1회 제한과 작성자·가려진 사연 차단은 유지한다. 향후 `visibility='private'` 상태도 거부하도록 준비했다. `anon` 직접 실행 권한은 제거한다.

격리된 Supabase PostgreSQL 이미지에서 [SQL 계약 시험](../../tests/vote-story-contract.sql)을 실행해 최초 선택, 동일 선택 재시도, 한 번 변경, 두 번째 변경 거부, 본인·비공개 사연 거부, 익명 거부를 확인했다. 지연 트리거를 둔 **동일 계정의 동시 최초 요청 2건**은 둘 다 결과 `votesA=1`을 받았고, 최종 투표 행 1개·집계 1·변경 횟수 0을 확인했다. 임시 컨테이너는 삭제했다. 이는 로컬 PostgreSQL의 축소 스키마 시험이며, 니편내편 운영 RLS·REST·실제 계정·브라우저 시험은 아니다. SQL은 운영 DB에 **미적용**이다.

## 운영 반영 전 경계

사연·댓글의 직접 쓰기 정책은 운영 DB에 남아 있어 브라우저가 서버의 포텐스 검사를 우회할 수 있다. 서버 인증 저장과 실제 계정 시험이 끝나기 전 [사연 정책 초안](sql/story-write-boundary.sql)·[댓글 정책 초안](sql/comment-write-boundary.sql)을 적용하지 않는다. 작성자 비공개와 AI 하루 3회 서버 제한도 완료되지 않았다. 이 코드는 검토·시험용 브랜치에 보존하고, 공개 `main` 배포와 구분한다.
