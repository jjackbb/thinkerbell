# 계정별 댓글 공감 적용 — 2026-09-25

최신 기능 기준은 [PLAN](../../PLAN.md)이다. 사용자는 댓글별 **계정당 1회 공감·재클릭 취소**와, 계정별 이력이 없는 과거 표시 숫자의 **0 재설정**을 확정했다. 이 문서는 운영 DB 변경과 로컬 화면 변경의 증거 범위를 분리한다. 댓글 본문·작성자 정보는 조회하지 않았다.

## 적용 전 상태와 데이터 선택

운영 DB에는 댓글 21건이 있었다. 그중 `likeCount > 0`인 댓글 3건의 합계는 31, 최댓값은 16이었다. `comment_likes` 같은 계정별 기록은 없었고 이전 `like_comment` 함수는 요청받은 `+1/-1`로 숫자만 바꿨다. 따라서 기존 31을 계정에 귀속할 근거가 없었다. 사용자 결정에 따라 31을 이관하지 않고 해당 표시값을 모두 0으로 바꿨다. 이 변경은 과거 공감 기록을 복원하거나 삭제한 계정을 특정한 결과가 아니다.

## 운영 DB에 적용한 변경

- [마이그레이션 `20260925075943`](../../backend/supabase/migrations/20260925075943_comment_likes_account_scoped.sql)은 변경 전 집계 21/3/31/16과 테이블 부재를 확인한 뒤 `comment_likes(comment_id, user_id, created_at)`를 추가했다. 댓글·인증 계정 삭제에 따른 외래키 연쇄 삭제, 조합별 유일성, 본인 행만 읽는 RLS를 적용했다. 익명 역할에는 테이블 권한이 없고 인증 역할에는 직접 쓰기 권한 없이 SELECT만 있다. 기존 공감 숫자 31은 0으로 재설정했다.
- 같은 마이그레이션은 기존 `like_comment(text, integer)` 호출 모양을 유지하되 `+1`을 **공감 상태로 만들기**, `-1`을 **공감 상태 해제**로 해석한다. 댓글·부모 사연을 잠그고 로그인 여부·숨김/차단 상태를 확인한 후 계정별 행을 추가하거나 제거한다. 중복 `+1`과 반복 `-1`은 추가 증감하지 않는다. 익명 실행 권한은 제거했다.
- [마이그레이션 `20260925080558`](../../backend/supabase/migrations/20260925080558_sync_comment_like_cascades.sql)은 계정 탈퇴 등으로 공감 행이 연쇄 삭제돼도 댓글 숫자를 다시 계산하는 트리거를 추가했다. 공감 함수도 이 트리거가 확정한 숫자를 반환하도록 변경했다. 작성자 비공개 사연을 위한 `visibility` 필드는 아직 없으므로 공감 함수의 해당 검사는 미래 상태에 대비한 조건일 뿐, 현재 작성자 비공개 보호의 증거가 아니다.

두 SQL 모두 먼저 명시적 트랜잭션 안에서 실행하고 `ROLLBACK`해 사전 조건과 적용 가능성을 확인했다. 그다음 니편내편 쓰기 MCP로 두 마이그레이션을 운영 프로젝트 `vzhyhadjtaqbapicjrco`에 적용했다. 적용 직후 독립 재조회에서 댓글 21건의 공감 합계가 0이고 `comment_likes`가 0건이었다.

## 권한·동작 검증 범위

기존 인증 계정 두 개의 ID를 SQL 내부에서 골라 `authenticated` 역할과 JWT `sub`를 흉내 냈다. 시험 데이터 변경은 `BEGIN`/`ROLLBACK`으로 되돌렸다.

| 동작 | 관찰 |
|---|---|
| 첫 계정 `+1`, 같은 요청 반복 | 댓글 숫자 1 유지 |
| 인증 역할의 직접 공감 행 INSERT | 권한 오류로 거부 |
| 두 번째 계정의 첫 계정 기록 SELECT | 0건 표시 |
| 두 번째 계정 `+1` | 댓글 숫자 2 |
| 두 번째 계정 `-1`, 같은 요청 반복 | 댓글 숫자 1 유지 |
| 남은 공감 행 삭제(계정 삭제 연쇄 효과에 준함) | 트리거로 댓글 숫자 0 |
| 시험 뒤 운영 재조회 | 공감 행 0건, 댓글 공감 합계 0 유지 |

로컬 공개키로 `comment_likes?select=comment_id&limit=0` 익명 REST 조회 시 HTTP 401과 DB 코드 `42501`을 받았다. 이는 익명 조회 거부 증거다. **실제 로그인 JWT를 통한 REST, 계정 전환·기기 변경, 계정 탈퇴, 화면 클릭은 시험하지 않았다.** DB 역할 모의 시험을 사용자 과업 완료로 해석하지 않는다.

## 화면과 출시 경계

[로컬 화면 코드](../../frontend/src/App.tsx)는 로그인 계정의 공감 행을 읽어 본인 상태를 표시하고, 서버가 반환한 숫자로만 화면을 갱신한다. 같은 댓글의 요청 중복을 막고 저장 실패에는 기존 상태를 유지한다. [댓글 버튼](../../frontend/src/components/StoryDetailModal.tsx)은 요청 중 비활성화되고 `aria-pressed`로 상태를 알린다. `npm run lint`, `npm run build`, `git diff --check`가 통과했다. 빌드에는 기존 500 kB 초과 청크 경고가 남았다. **이 화면 변경은 아직 Vercel에 배포하거나 실제 로그인 브라우저로 검증하지 않았다.** 이전 배포 클라이언트가 구형 `+1/-1`을 보내더라도 새 DB 함수는 중복 숫자 증감을 막는다.
