# 사용자 시험 전 브라우저·Auth 설정 기술 확인 — 2026-09-28

> **시점별 근거 문서:** 아래 상태·결정·SQL 안내는 제목 날짜와 후속 기록 당시의 이력입니다. 현재 작업 지시는 [최신 인수인계](README.md)와 [PLAN](../../PLAN.md)을 따릅니다. 과거 미적용·미실행 표시만 보고 재실행하지 않습니다.


대상은 현재 **로컬 개발 서버 코드**와 니편내편 운영 Supabase 프로젝트 `vzhyhadjtaqbapicjrco`다. Chrome 모바일 화면 크기는 390×844이었다. 실제 이용자나 메일함은 쓰지 않았고, 관리자 API에서 확인 처리한 임시 계정 A·B와 가상 사연만 만들었다. 매 시험 후 사연·접근 무효화 행·계정 두 개의 삭제 및 재조회가 통과했다. 이 결과는 Preview 배포나 실제 사용자의 브라우저 관찰로 옮겨 적지 않는다.

| 확인 항목 | 결과 |
| --- | --- |
| 로그인·계정 전환 | A가 브라우저에서 로그인해 자신의 비공개 사연을 마이페이지·상세에서 확인했다. 같은 브라우저 세션을 B로 바꾸자 A의 제목·본문·상세 URL이 사라졌다. B 로그아웃 뒤에도 본문·옛 브라우저 프로필 저장값이 없었다. `PASS` |
| Realtime 화면 제거 | B가 공개 사연 상세를 열고 B 계정의 접근 무효화 구독이 연결된 뒤 A가 `set_story_visibility`로 비공개 전환했다. B의 열린 상세·피드 원문·`?story=` URL이 제거됐다. `PASS` |
| 첫 Realtime 시도 | 초기 자동화는 계정 전환 전 게스트 구독과 B 구독을 구분하지 않고 **어느 채널이든** 연결되면 A의 비공개 전환을 실행했다. 20초 안에 B 화면이 지워지지 않아 `FAIL`로 기록했다. 이는 구독 교체 시점 경쟁일 가능성이 있으나 그 원인을 단정할 증거는 없다. 이후 계정별 채널 이름을 분리하고 **B 전용 구독 연결**을 기다린 새 시험은 통과했다. 구독이 교체되는 바로 그 순간의 누락 가능성은 별도 점검 대상으로 남긴다 |
| AI 실패 화면 | 같은 로컬 Chrome에서 별도 임시 계정·AI 방을 만들고 **브라우저의 `/api/chat-stream` 응답만 가로챘다.** 완료 신호 없이 끊긴 부분 응답에는 “다시 보내기”가 나타났고 입력 말풍선이 남았다. 재시도 응답의 `ai_save_failed`에도 저장 실패 안내·입력 말풍선이 남고 마무리 버튼과 새 입력 전송이 막혔다. `PASS`는 화면 복구에 한정하며 실제 공급자·서버 저장·횟수 처리는 이 시험으로 확인하지 않았다 |

계정 변경 시 이전 계정의 열린 사연·댓글·AI 방·프로필과 진행 중인 계정별 상태를 먼저 비우도록 로컬 코드를 수정했다. 초기 사연·댓글 읽기와 Realtime 구독은 현재 계정에 묶고, 늦게 끝난 이전 계정 요청은 화면에 반영하지 않는다. 브라우저 프로필의 `nipyeon_user`는 더 이상 로그인 근거로 읽거나 저장하지 않는다. 로그인 창을 닫으면 앞 계정의 이메일·비밀번호 입력도 비우며, 로그아웃 후 다시 열린 창에서 빈 입력을 확인했다. 비공개 상세는 현재 로그인한 작성자에게만 렌더링한다. 최신 코드의 `npm run lint`, `npm run build`, `git diff --check`가 통과했다. 이 수정은 [최신 Preview](2026-09-28-release-gates.md)에 배포해 Ready·건강 API·번들 문자열을 확인했다. **배포 Preview의 실제 브라우저 과업과 Production 배포는 아직 확인하지 않았다.**

AI 실패 화면 시험의 첫 자동화 시도는 이전 시험 브라우저의 삭제된 임시 계정 세션이 남아 로그인 화면을 찾지 못해 중단됐다. 이때 만든 가상 행은 정리 완료로 확인했다. 브라우저 저장소를 비우고 새 계정으로 다시 시작한 시험은 위 항목을 통과했고, 임시 AI 방·사연·접근 무효화 행·계정을 삭제해 재조회 0건을 확인했다.

비밀번호 재설정의 Supabase Auth 설정은 사용자가 로컬에 둔 니편내편 Management API 토큰으로 적용했다. 프로젝트 ref와 현재 Site URL을 먼저 확인하고, **기존 Redirect URL을 보존**하며 `https://thinkerbell-eight.vercel.app/?auth=recovery` 및 `https://thinkerbell-*-jjackbb-projects.vercel.app/**`를 추가했다. [한국어 재설정 템플릿](../email-templates/reset-password.ko.html)의 제목·본문도 저장했고 Management API 재조회 값이 일치했다. 적용에 사용한 임시 토큰은 로컬 `.env`에서 제거했다. 실제 메일 도착·링크·비밀번호 변경·재로그인은 아직 시험하지 않았다.

비밀번호·메일 주소·토큰·사연/대화 원문은 이 문서에 기록하지 않는다. 임시 계정의 앱 동작은 실제 A·B 메일함 인증이나 사용성 검증의 대체 증거가 아니다.
