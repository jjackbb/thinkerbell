1. 목표와 첫 공개 범위

핵심 기능과 계측을 정상화한 뒤 커뮤니티·SNS에 소개 글과 링크를 게시하고, 자발적 이용·피드백부터 확인합니다. 직접 모집·동석 관찰·특정 참여 인원·고정 관찰 기간을 공개 조건으로 두지 않습니다.

현재 상태 (9월 30일 운영 기준): 운영 앱·직접 쓰기 차단·핵심 연동 검증은 완료 기록이 있습니다. 사용자가 확정한 ‘정상 답변 완료와 저장 결과 분리’를 운영에 복원했고, 가상 스트림 4종의 브라우저 집계와 운영 GA4 수신을 확인했습니다. 이번 시험에서는 실제 AI 호출·대화 저장을 수행하지 않았습니다. 실제 커뮤니티·SNS 게시는 아직 하지 않았습니다.

최신 사용자 결정: 답변 생성 완료 시 ai_chat_turn1/turn3, 저장 결과는 별도 operation_success/error로 기록합니다. 저장 실패 미차감·입력 보존·새 답변 재요청은 유지합니다. 자정 횟수 전환 확인은 이번 범위에서 제외하며 설정을 변경하지 않습니다. 문서 정리 후 커밋·푸시·운영 배포는 승인됐습니다.

월 예산 상한은 10만 원이다. 포텐스는 사용자가 2026-09-25 기준 “내년 6월까지 무료지만 일일 한도가 있는 것으로 안다”고 설명한 조건을 전제로 한다. 정확한 종료일·일일 한도·현재 사용량은 아직 확인하지 못했다. 인증 메일은 Resend 무료 요금제와 발송용 도메인 1개를 사용한다. 사용자는 jjackbb.com을 구매했다고 알렸고 발송용 하위 도메인 auth.jjackbb.com을 선택했다. 결제액·갱신액은 영수증으로 확인해야 한다. Resend Verified는 사용자 확인, DKIM·SPF 공개 DNS 값 일치는 직접 확인했다. 루트 DMARC 게시도 공개 DNS에서 확인했다. Supabase Auth SMTP 설정은 사용자 확인이고, 신규 가입 1건의 앱 복귀는 사용자 시험 보고와 Auth 확인 시각으로 대조했다. 설정 기록과 시험 기록은 증거 범위를 구분한다. 메일 설정 기록 당시 Resend 무료 한도는 월 3,000통·하루 100통이며, 유료 전환은 자동으로 진행하지 않는다. 서버·DB 비용은 실제 계정의 요금제와 사용량을 확인한다. 2. UX·기능·데이터 설계

UX 우선순위

전체 디자인 교체보다 첫 사용 흐름에서 발견한 문제를 먼저 해결한다. 사용자가 UX/UI를 판단할 수 있도록 화면별 목적·버튼·성공·실패 상태를 함께 검토한다.

순서개선 대상설계와 완료 기준
1저장·등록 결과사연·댓글·닉네임·신고는 서버 성공 확인 후 완료 표시. 실패하면 입력을 보존하고 재시도 가능
2현재 위치와 AI 발견활성 탭을 명확히 표시. 사연 상세에서 댓글을 오래 탐색하지 않아도 AI 진입을 발견할 수 있게 배치
3모드 이해‘상대와 대화하기’에는 사연 속 상대 역할의 AI임을 설명. ‘공감 대화’에는 내 입장·양쪽·상대 입장 중심 선택을 설명
4AI 대기·실패·복원응답 대기, 부분 응답 실패, 재시도, 저장 실패를 구분. 새로고침·다른 기기에서도 저장된 대화 복원
5마무리와 도움 평가마무리는 대화를 보존. 기존 기분·한 줄 소감 입력은 제거하고 선택형 도움 평가 1문항 제공
6개인 기록과 운영내 사연·참여 내역·숨긴 사연 복원 경로 정리. 신고·문의가 실제 운영 목록에 접수되도록 연결

랭킹·투표 제한·빈 화면·준비 중 안내는 실제 동작에 맞춰 설명한다. 모바일 키보드에 입력창이나 버튼이 가려지는 문제도 핵심 흐름에 포함해 확인한다.

공개·숨김·AI 권한

상황동작
남의 글을 나에게만 숨김숨긴 이용자에게만 보이지 않음. 다른 이용자의 목록·접근 상태는 바뀌지 않음. 즉시 취소와 마이페이지 숨긴 목록에서 복원 제공
내 사연을 비공개로 변경다른 모든 이용자의 목록에서 숨기고 작성자만 확인할 수 있는 공간으로 이동. 타인의 원문·댓글 조회와 신규 투표·댓글 차단. 공유 링크·직접 API 요청에도 동일하게 적용
비공개 후 재공개기존 댓글·투표를 보관했다가 다시 표시. 재등록·재집계로 중복을 만들지 않음
비공개 중 새 댓글작성자를 포함한 모든 이용자가 새 댓글을 달지 못함. 기존 댓글은 보관 후 재공개 시 다시 표시
비공개 사연의 작성자자기 사연으로 새 AI 대화 생성 가능
비공개 사연의 다른 이용자기존에 소유한 AI 대화는 계속 이용. 새 대화방 생성은 차단
기존 공감 대화의 관점 변경보존된 사연 맥락으로 변경 가능. 비공개 원문을 다시 조회하지 않음

비공개 안내에는 이미 만들어진 다른 이용자의 AI 대화에 포함된 내용은 남을 수 있음을 명시한다. 비공개를 기존 대화에서까지 내용을 지우는 기능으로 설명하지 않는다.

작성자 비공개 사연은 마이페이지 ‘작성한 사연’ 안에서 공개·비공개를 구분해 확인한다. 다시 공개해도 원래 createdAt을 유지하므로 공개 목록에서 새 사연처럼 위로 올리지 않는다. 비공개 구현은 공개 조회 정책만 바꾸면 완료되지 않는다. 댓글 조회·쓰기, 투표·공감·신고 등 서버 함수, 실시간 화면 갱신, 새 AI 대화방 생성과 기존 대화 이어하기를 함께 확인한다. 접근 경계 점검

가입·투표·AI 이용 규칙

  • 가입은 이메일 확인 후 완료한다. 실제 외부 주소로 인증 메일 발송, 재발송, 만료, 확인 후 앱 복귀까지 연결한다. 게스트의 공개 사연 둘러보기는 유지한다.
  • 기존 가입 여부는 이메일 주소 입력만으로 보여주지 않는다. 해당 메일함의 소유 확인 링크를 사용한 뒤 가입 가능·가입 확인 미완료·가입 확인 완료를 구분해 안내한다. 새 가입의 확인 메일은 한 통이며, 비밀번호를 잊은 기존 이용자는 재설정 메일을 요청할 수 있다. 결정과 검증 범위
  • 투표는 같은 선택 재클릭 무시, 반대쪽으로 한 번 변경, 취소 없음으로 유지한다. 본인 사연 투표 제한도 서버에서 확인한다.
  • 댓글 공감은 로그인 계정당 댓글별 1회만 누를 수 있고, 다시 누르면 취소한다. 연타·재시도·기기 변경으로 숫자가 중복 증감하지 않게 서버에서 확인한다. 과거 계정별 기록 없이 남은 표시 숫자 31개는 사용자 결정에 따라 0으로 재설정했다.
  • 남의 사연으로 새 AI 대화는 하루 3회, 한국 시간 기준으로 적용한다. 내 사연과 이미 정상 이용한 대화 이어하기는 추가 차감하지 않는다.
  • 전환 시각 이전에 만든 AI 대화방 7개는 모두 무료 이어하기로 인정한다. 과거 자동 저장 이력만으로 정상 답변 여부를 추정해 다시 차감하지 않는다.
  • 새 대화의 첫 요청 중에는 횟수를 예약하고, 첫 정상 답변이 완료되면 차감한다. 실패·완료 전 취소는 예약을 반환한다. 실패한 방을 다시 열었다는 이유로 제한을 우회하지 못하게 한다.
  • 화면에 AI 답변이 나왔어도 DB 저장이 실패하면 차감하지 않는다. 입력과 미저장 답변을 경고와 함께 화면에 남기고, 재시도는 새 AI 답변을 요청한다. 저장 완료 여부와 답변 완료 계측은 구분한다.
  • 개인 숨김은 사연 노출에만 적용한다. 그 사연에서 이미 소유한 AI 대화방은 AI 목록에서 계속 열 수 있으며, 별도 삭제는 이용자가 선택한다.
  • 첫 공개에서는 AI 대화 내용을 자동 삭제하지 않는다. 이용자의 대화 삭제·계정 탈퇴 때만 삭제한다. 도움 평가의 최대 30일 보관은 별개다.
  • 하루 3회의 귀속 날짜는 대화방을 연 날이 아니라 첫 실제 AI 요청을 서버가 받은 한국 날짜로 고정한다. 자정 후 답변이 완료돼도 성공한 요청은 그 날짜의 몫으로 확정한다. 횟수 예약·완료·반환 기록은 종료 후 30일 보관하며, 대화 본문·도움 평가의 보관 규칙과 구분한다.
  • 콘텐츠 검사 실패는 안전 판정으로 처리하지 않는다. 입력을 보존하고 ‘다시 검사’로 실제 포텐스 API를 호출한다. 수정된 내용에는 다시 검사한다.

3. 버튼 이벤트·GA4·도움 평가

2026-10-09 팀회의 후 확정: 핵심 흐름 한정에서 모든 일반 사용자 화면·버튼/링크/카드 행동·기능 결과로 확대한다. 일반 가입·로그인·탐색을 포함하고 민감 화면·행동은 제외한다. 신규 이벤트는 GA4에만 보내며 기존 내부 DB 9종은 유지한다. 로컬 구현·검증 상태는 최신 인수인계, 전체 행동 목록은 계측 목록을 따른다. 사용자는 기존 가입 계정이 테스트·팀원 계정임을 확인했다. 별도 재동의 전환은 생략하고 기존 동의·거부 선택을 유지하며 확대된 안내를 적용한다. 확정 내용에 기록한다. 운영 배포는 아직 9월 30일의 핵심 흐름 수집 버전이다.

모든 노출 버튼에 기능 계약을 붙인다. 기존 소스의 버튼 위치 153곳을 출발점으로, 실제 화면의 조건부·반복 요소를 대조해 최종 목록을 만든다.

2026-09-28 현재 TSX의 정적 <button> 선언 174곳에 고유한 data-button-id를 부여하고 위치·ID 목록으로 재집계했다. 실제 발송 기능이 없는 알림 토글 3개는 첫 공개의 “준비 중” 범위에 맞춰 제거했다. 핵심 버튼 계약과 174개 화면별 계약 지도에 선행 조건·성공·실패·이벤트·검증 케이스를 구분했고 ID 누락·중복 0개를 확인했다. 선택한 핵심·조건부 동작과 운영 GA4는 검증 기록이 있다. 174개 모든 상태의 전수 통과를 뜻하지 않으며, 현재 남은 범위는 실행 인수인계를 따른다.

버튼 문구를 바꿔도 같은 행동의 ID는 유지한다. 기능 검증 대상과 GA4 전송 대상은 구분하며, 민감한 위기 지원 행동 등은 외부 전송 제외 사유를 명시한다.

클릭을 성공으로 세지 않는다. 재시도·연타·화면 재렌더·계정 교체로 완료 이벤트가 중복되거나 누락되지 않게 한다. AI 1턴은 사용자의 메시지에 대한 정상 응답 한 쌍이며, 실패한 전송은 턴 수에 포함하지 않는다. GA4는 일반 화면·행동·기능 결과와 기존 핵심 지표를 함께 보낸다. 일반 가입·로그인·비밀번호 재설정/변경·닉네임 수정은 입력값 없이 작업 종류와 결과만 수집한다. 신고·문의·위기 지원, 개인 숨김·비공개 변경·탈퇴·개인 기록 삭제 및 관리자 전용 화면은 수집하지 않는다. 도움 평가 선택값·점수도 제외한다. 입력 타자·임의 텍스트·스크롤 전수 추적은 범위에 포함하지 않는다.

GA4 수집 방식

  • 이용자가 동의한 뒤 태그를 로드하는 기본 동의 방식으로 구현한다. 동의 전·거부 상태에서는 Google에 전송하지 않고 과거 행동을 소급 전송하지 않는다. 설정에서 선택을 변경할 수 있게 한다. Google 동의 모드
  • 선택적인 내부 행동 분석 로그도 동의 범위에 맞춘다. 기능 저장·인증·오류 처리에 필요한 기록은 목적을 구분해 안내한다.
  • 사연·댓글·대화·신고 원문, 이메일·닉네임·계정 ID, 도움 평가값을 GA4로 보내지 않는다. URL·페이지 제목·오류 메시지도 정제한다.
  • 화면 전환의 수동 페이지뷰는 고정된 화면 이름으로 보낸다. Google 자동 페이지뷰는 계속 끄고 재렌더는 새 화면으로 세지 않는다. 앱의 임의 방문 ID로 GA4의 session_id를 덮어쓰지 않는다. 동의 뒤 Google 태그가 만드는 기본 세션 이벤트는 별개로 확인한다.
  • release_id, 화면, 진입 위치, 모드, 신규·이어하기, 모집 경로, 오류 종류를 기준으로 분석한다. 내부 시험과 운영 데이터를 분리한다. 9월 30일 구현: ?source=community와 ?source=sns를 공유에 사용하며 지정하지 않은 값은 unattributed다. 별도 기술 시험은 ?source=qa → technical_test로 구분한다. 쿼리 원문·임의 플랫폼 이름은 전송하지 않는다. 분석 동의 뒤에만 해당 범주를 탭 세션에 보관하고 동의 철회 시 지운다.
  • conversation_type=new는 새 방 생성, continuation은 기존 방·서버 복구 방 재진입을 뜻한다. 단순히 과거 말풍선이 없다고 새 방으로 세지 않는다. ai_chat_turn1은 열린 대화 회차의 첫 정상 완료 답변이며 신규/이어하기를 나누어 분석한다. 서버의 명시적 답변 완료 신호와 비어 있지 않은 표시 내용을 확인해 집계한다. 이후 저장에 실패해도 답변 완료는 유지하고 저장 실패는 별도로 기록한다. ai_chat_turn3도 같은 완료 기준을 사용한다. 부분 응답·빈 응답·완료 신호 없는 종료는 세지 않는다. 횟수 차감과 도움 평가 가능 여부는 정상 저장을 기준으로 유지한다.
  • GA4와 내부 이벤트 저장은 서로 기다리지 않는다. 분석 전송 실패가 제품 사용을 막지 않게 한다.

도움 문항은 “이 AI 대화가 도움이 되었나요?”로 한다. 선택지는 ‘전혀 도움 안 됨 / 별로 도움 안 됨 / 보통 / 조금 도움 됨 / 매우 도움 됨’이며 건너뛰기를 제공한다. 두 AI 모드 모두 정상 저장된 답변 1회 이상 뒤 ‘대화 마무리’를 누르면 평가를 보여준다. 전환 전 옛 방도 과거 말풍선만으로 평가를 열지 않고 새 정상 저장 답변을 받은 뒤 연다. 마무리는 대화를 보존하며 삭제는 별도 행동이다. 제출 성공을 확인하고 평가값은 GA4에 보내지 않는다.

개인별 평가는 최대 30일 보관하고 대화 삭제·탈퇴 시 함께 삭제한다. 이후에는 월 단위·두 모드 합계에서 서로 다른 점수 응답자 최소 5명을 월말에 확인할 수 있는 경우만 전체 유효 평가 수와 4~5점 수를 남긴다. 31일인 달의 초반 평가가 월말 전에 만료돼 응답자 수를 증명할 수 없으면, 실제로 5명 이상이었을 가능성이 있어도 그 달의 임시 합계를 버린다. 건너뛰기, 작은 집단, 일별·모드별·점수별 셀은 장기 보존하지 않는다. 이 방식의 호환 SQL은 격리 시험 후 운영 DB에 적용했고 구조·권한을 조회했다. 일일 정리는 9월 29·30일 성공 기록이 있으며 실제 월말 집계는 아직 확인하지 않았다. 미응답을 불만족으로 처리하거나 응답자 만족도를 전체 이용자의 만족도로 표현하지 않는다.

4. 검증과 실제 공개

단계작업다음 단계로 가는 기준
1. 환경 확인실제 Vercel·Supabase 프로젝트, 원격 DB·권한·요금제, GA4 소유 계정, 메일 발송 구성을 확인대상과 접근 권한 확인. 누락 구조와 기존 구조의 차이 기록
2. UX·기능·계측 구현위 우선순위대로 화면 상태·저장·서버 권한·이벤트를 함께 연결각 버튼의 기능·이벤트·실패 계약 구현
3. 시험 환경 검증별도 시험 데이터로 정상·오류·권한·중복·복원 검증핵심 시나리오 통과, 공개를 막는 결함 0
4. 운영 반영호환 가능한 DB 변경 → 앱 배포 → 필요한 권한 제한 적용운영 구성과 배포 버전 일치
5. 운영 확인실제 외부 인증 메일·포텐스 응답·DB 저장·GA4 수신 확인공개 URL에서 핵심 과업 완주와 계측 확인
6. 커뮤니티·SNS 공개공개 글·링크 게시 후 자발적 이용·피드백 확인운영 버전·게시 경로·게시 시각 기록
7. 보고서 대조처리된 GA4 보고서와 통제된 시험·앱 기록 비교누락·중복·환경 혼입을 설명할 수 있음

기존 공개 주소를 기준으로 배포 대상을 확인한다. 운영 DB를 시험 환경으로 잘못 연결하지 않는다. 운영 구조를 읽었더라도 기존 데이터의 이관과 역할별 권한 검증 없이 마이그레이션을 적용하지 않는다.

필수 검증은 다음을 포함한다.

  • 가입·계정: 외부 이메일 인증, 재발송·만료·복귀, 로그인 실패·세션 복원, 같은 기기의 계정 교체, 닉네임 저장·탈퇴.
  • 사연·참여: 등록·수정·삭제·취소, 연타와 통신 실패, 투표 변경 제한, 댓글·공감 중복, 새로고침 후 일치.
  • 권한: 작성자·타인·제3자·비로그인으로 개인 숨김, 비공개·재공개, 기존 AI 이용, 신규 AI 차단을 직접 API 요청까지 확인.
  • AI: 정상 응답, 첫 실패 후 재시도, 부분 응답 후 오류, 완료 신호 없는 종료, 저장 실패, 동시 요청, 횟수 예약·반환.
  • 평가·계측: 평가 제출·건너뛰기·삭제, 동의·거부·철회, 중복 이벤트, 금지 정보 전송, 분석 장애 중 정상 기능 이용.
  • 운영·기기: 신고·문의 접수와 운영자 처리, Chrome 기기 모드·키보드·스크롤·뒤로가기. 사용자는 실물 휴대폰 대신 Chrome 기기 모드를 선택했다. 실물·Safari 검증은 후속 범위이며 완료로 기록하지 않는다.

실제 연동 검증과 오류를 주입한 시험은 구분해 기록한다. 결과는 PASS / FAIL / NOT_RUN / BLOCKED로 남긴다.

데이터 손실·타인 정보 노출·핵심 저장 장애가 발생하면 해당 기능을 중단하거나 검증된 버전으로 복구한다. DB를 파괴적으로 되돌리거나 기존 데이터를 삭제하는 방식으로 복구하지 않는다.

5. 공개 후 개선과 완료 판정

커뮤니티·SNS 공개 후 실제 이용과 자발적 피드백부터 확인한다. 2026-09-30 사용자 결정에 따라 직접 모집·진행자 동석 관찰은 당장 요구하지 않는다. 게시 경로·시각과 배포 버전을 기록하고 기술 시험 구간을 분리한다. 공개 게시를 통한 자발적 이용, 별도 직접 모집, 진행자의 도움을 받은 이용을 구분한다. 직접 관찰이나 인터뷰를 수행하지 않았다면 행동 데이터와 자발적 피드백만으로 확인한 범위를 명시한다.

아래 과업 관찰·인터뷰는 필요할 때 실행할 후속 방법이며 이번 공개의 선행 조건이 아니다.

관찰 과업은 ‘사연 찾기 또는 작성하기 → 원하는 AI 모드 선택 → 실제 대화 → 다시 찾기’로 구성한다. 버튼 위치를 미리 알려주거나 3턴을 억지로 채우게 하지 않는다. 실제 고민은 공개 가능한 범위에서 사용자가 선택하게 한다.

짧은 인터뷰에서는 세 가지를 확인한다.

  • 무엇을 기대했고 어디에서 막혔는가?
  • AI의 어떤 답변이 도움이 됐거나 도움이 되지 않았는가?
  • 다시 이용한다면 어떤 상황에서 이용하겠는가?

개선은 다음 순서로 반복한다.

  1. 수집 오류부터 구분한다. 이벤트 누락이나 AI 장애를 UX 문제로 오인하지 않는다.
  2. 문제의 근거를 묶는다. GA4의 이탈·실패 지점, 실제 과업 관찰, 이용자의 설명을 함께 본다.
  3. 한 번에 검증할 문제 하나를 선정한다. 과업 중단·데이터 손실을 우선하고, 다음으로 반복되는 실패·발견성 문제를 본다.
  4. 변경 전에 판정 기준을 적는다. 대상 행동, 바꿀 요소, 기대하는 변화, 함께 확인할 부작용을 정한다.
  5. 수정하고 새 버전으로 배포한다. 관련 기능·권한·이벤트만 필요한 범위로 재검증한다.
  6. 새 이용자에게 같은 과업을 확인한다. 같은 사람이 사용법을 익힌 효과와 제품 개선을 구분한다.
  7. 개선·악화·판단 보류로 기록한다. 나아지지 않았다면 원복하거나 가설을 수정해 다시 검증한다.

GA4 비교에는 버전별 실제 분자·분모, 유입 경로, 기기, 신규·이어하기, 관찰 기간을 함께 남긴다. 공개 초기에는 작은 숫자를 퍼센트만으로 강조하지 않는다. 처리 중인 보고서는 잠정값으로 다루며, 일반 데이터 처리에 24~48시간이 걸릴 수 있음을 반영한다. GA4 처리 시간

첫 개선 사이클의 완료물은 정상 작동하는 운영 버전, 버튼·이벤트 목록과 검증 기록, 공개 이후 기준선, 실제 문제의 근거, 개선 배포, 동일 기준의 재검증 결과다. 결과에는 ‘기능 수정 확인’, ‘사용성 개선 관찰’, ‘정량 변화 관찰’, ‘표본 부족으로 판단 보류’를 구분한다. 배포 완료나 클릭 증가만으로 목표 달성을 선언하지 않는다.

이 계획이 최신 설계 기준이다. 기존 초안의 3턴 대표 지표·고정 관찰 기간·성인 인증 포함 출시 제안은 이번 결정으로 대체하며, 구현 착수 시 관련 문서도 함께 맞춘다.
