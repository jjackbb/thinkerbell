# 유저플로우 점검

버튼과 요소를 하나씩 놓고 **"유저가 이걸 왜 누르나"** 를 따져, 필요 없는 것을 걷어내는 작업이다.
GA4 이벤트는 여기서 살아남은 요소에만 붙인다. 지울 버튼에 이벤트를 심으면 데이터가 오염된다.

작성 시작: 2026-08-24

결과: 사연 11 → 8건.

### 이번에 새로 찾은 결함

**사연을 지워도 댓글·투표가 남는다.**

- 증상: 위 3건을 지우자 고아 댓글 1건이 남았다 (이번엔 직접 지웠다).
- 원인: `stories`를 가리키는 **외래키가 하나도 없다.** `comments.storyId`,
  `votes.storyId` 모두 그냥 문자열 컬럼이다. 앱의 `confirmDeleteStory`
  (`App.tsx:677`)도 `stories` 행 하나만 지운다.
- 범위: **탈퇴는 무사하다.** `delete_my_account()`가 사연·댓글·투표·신고를
  함수 안에서 직접 다 지운다. 문제는 **사연 한 건 삭제** 경로뿐이다.
- 왜 문제인가: 주인 없는 댓글이 DB에 계속 쌓인다. 지웠다고 생각한 글에 달린
  남의 댓글이 그대로 남아 있는 것이라, 개인정보 관점에서도 정리해야 한다.
- **해결: 외래키를 걸었다** (마이그레이션 `link_story_children_with_foreign_keys`).
  이제 앱이든 SQL이든 나중에 만들 관리자 화면이든, 어느 경로로 지워도 DB가 정리한다.

  | 테이블 | 규칙 | 왜 |
  |---|---|---|
  | `comments` | `on delete cascade` | 댓글은 사연과 운명을 같이한다 |
  | `votes` | `on delete cascade` | 마찬가지 |
  | `ai_personas` | `on delete set null` | **사연이 없어져도 내가 나눈 대화는 내 것이다** |
  | `ai_chat_usage` | `on delete set null` | "썼다"는 사실이 남아야 무료 횟수 정산이 맞다 |
  | `reports` | 걸지 않음 | `targetId`가 사연과 댓글을 **모두** 가리켜(`targetType`으로 구분) 외래키를 걸 수 없다 |

  외래키 컬럼 4개에 색인도 함께 만들었다. 없으면 사연을 지울 때마다 딸린 표를 전부 훑는다.

  **확인:** 임시 사연에 댓글·투표·AI 대화방을 달아 실제로 지워봤다. 댓글·투표는 0이 되고,
  AI 대화방은 남은 채 `storyId`만 `null`이 됐다. `sync_story_comment_count` 트리거
  충돌도 없었다. 검사 데이터는 전부 치웠다.

## 2. 사연 상세

사연 카드를 누르면 열리는 모달. 읽고, 편을 들고, 댓글을 다는 곳이다.

### 모달 상단 바

| 요소 | 유저가 왜 누르나 | 누르면 뭐가 되나 | 판정 | 결정 |
|---|---|---|---|---|
| 로고 `니편내편` | 처음으로 돌아가려고 | **아무 일도 안 일어남** | **미끼** — 코랄색 로고라 눌릴 것처럼 보이는데 `onClick`이 없었다. 모달 안에서 홈으로 갈 일도 없어 붙일 동작이 없었음 | **`사연` 제목으로 교체 완료** |
| `⋮` 메뉴 | 신고/수정/삭제하려고 | 드롭다운 | 유지 | **유지** |
| `X` 닫기 | 나가려고 | 모달 닫힘 | 유지 | **유지** |

**단, 입력창에 글을 쓰는 중이면 무시한다.** 댓글을 쓰다 무심코 누르면 읽던 자리와 주소를
통째로 잃는데, 그건 닫으려던 게 아니다.

### 댓글

| 요소 | 유저가 왜 누르나 | 누르면 뭐가 되나 | 판정 | 결정 |
|---|---|---|---|---|
| 진영 필터 (`전체`/`니 편`/`내 편`) | 반대편 의견을 찾아보려고 | 댓글 목록 필터 | 한때 '해소 원칙에 어긋난다'고 봤으나 **기각** | **유지** |
| 정렬 (`최신순`/`좋아요 순`) | 좋은 댓글부터 보려고 | 목록 정렬 | 유지 | **유지** |
| `입력` 버튼 | 댓글 등록하려고 | 댓글 저장 | '입력'은 행동이 아니라 상태 | **`등록`으로 완료** |
| 댓글 입력창 | 쓰려고 | — | **초안이 사연 사이로 샜음** (아래) | **사연이 바뀌면 비우게 완료** |

**진영 필터를 남긴 이유:** 사람을 진영별로 *묶어서 대립시키는* 장치와, 반대편을
*이해하러 건너가는* 통로는 다르다. "반대편 의견은 뭐가 있는지 궁금해서 찾아보고 싶다"는
동선은 해소를 막지 않는다. 형태만 보고 원칙을 기계적으로 적용하지 않는다.

### 이번에 새로 찾은 결함

**⚠️ 댓글 초안이 다른 사연으로 새어 나갔다**

모달은 사연이 바뀌어도 다시 만들어지지 않는데 `commentText`를 비우지 않았다.
그래서 **A 사연에 쓰다 만 댓글이 B 사연 입력창에 그대로 따라갔다.** 익명 서비스에서
엉뚱한 사연에 등록되면 되돌릴 수 없다. 사연이 바뀔 때 초안·수정중·열린 메뉴를
모두 비우게 고쳤다.

**⚠️ 조회수가 DB에 전혀 쌓이지 않았다**

```ts
supabase.rpc('increment_story_view', { p_story_id: story.id });   // 요청이 안 나감
```

supabase 쿼리 빌더는 기다려 주기 전까지 요청을 보내지 않는다. `.then()`이 없어서
**네트워크 요청 자체가 발생하지 않았다.** 화면 숫자만 로컬로 오르고 DB는 그대로였다.
조회수는 신고 비율 판정의 분모라, 그만큼 분모가 실제보다 작았다는 뜻이다.

**마이페이지에서만 다른 길로 열렸다**

피드·주간랭킹·공유 링크는 전부 `openStoryDetail`을 거치는데 마이페이지만
`setSelectedStory`를 직접 불러 조회수 증가와 주소(`?story=`) 동기화가 통째로 빠졌다.
같은 사연인데 어디서 들어왔느냐에 따라 다르게 동작했다. 한 길로 통일했다.

### 밸런스 게임 배너 (1번 화면에서 보류했던 것)

| 요소 | 예전 | 지금 |
|---|---|---|
| 표수 | **하드코딩된 가짜 값** (782·450·820) | DB에 실제로 쌓임, 0부터 시작 |
| 저장 | 컴포넌트 상태만 +1, 새로고침하면 원상복귀 | `balance_votes` 테이블 (한 사람 한 표, 변경 1회) |
| 투표 전 비율 | **78% / 22%가 그대로 노출** | 봉인 게이지 — 사연 카드와 같은 규칙 |
| 비로그인 클릭 | 그냥 눌림 (저장 안 됨) | 로그인 안내 |
| 반응 속도 | 10초 뒤 확정 | 즉시 (9ms) |

10초 지연은 "눌렀는데 티가 안 나서 두 번 누르는" 상황을 만들고 있었다 — 이 감사에서
없애려던 **무반응** 그 자체였다.

**버튼 좌우 순서를 바꿨다.** 앱 전체가 왼쪽 = 니 편(인디고), 오른쪽 = 내 편(코랄)
규칙이라 게이지를 공유하면 버튼도 맞춰야 "왼쪽 버튼 색 = 왼쪽 막대 색"이 된다.
안 맞추면 왼쪽 버튼은 코랄인데 왼쪽 막대는 인디고가 된다. 감정을 대변하는 선택지
(`뚝배기 🔨`)가 '내 편' 코랄에 앉는 쪽이 색 언어와도 맞는다.

### 같은 규칙이 두 벌이던 것을 합쳤다

봉인 게이지 규칙이 `VoteResult.tsx`(흰 카드용)와 `BalanceGameSection.tsx`(검은 배너용)에
각각 한 벌씩 있었다. `VoteResult`가 색을 흰 배경 전제로 하드코딩하고 라벨도
'니 편/내 편'으로 박아둬서 재사용이 안 됐던 것이다.

`labels` prop과 `surface: 'light' | 'onyx'` prop을 뚫어 한 곳으로 합쳤다.
색은 전부 `index.css` 변수로 빠졌고 **컴포넌트 안에 hex가 하나도 없다.**
나중에 진영색을 리디자인할 때 이 파일은 이미 정리된 상태가 된다.
