# ST1 — 익명 사연 + 집단 판결/투표 서비스 UX

## 핵심 발견

- **AITA 피드 카드에서 판결(flair)은 "히어로"가 아니라 제목 아래 작은 pill이다.** 실측 순서: `작성자·시간(12px) → 제목(16px/600, 최대 3줄) → 판결 pill(14px) → 본문 3줄 → 투표수·댓글수`. 카드 높이 188~214px. — reddit.com DevTools 실측 2026-08-17 (A)
- **AITA에는 게이지/퍼센트가 아예 없다.** 판결 = "18시간 뒤 최다 추천 최상위 댓글의 판정"이라는 단일 승자 방식. FAQ가 폴 대신 업보트를 쓰는 이유를 명시: *"Upvotes let people vote without requiring they comment, so it works for lurkers."* — wiki/faq (A)
- **판결 색상 실측**: Asshole `#B8001F`, Everyone Sucks `#CC3600`, Not the A-hole·No A-holes here `#7193FF`, INFO `#D3D6DA`, UPDATE/META `#FFD635`. **NTA와 NAH가 같은 파란색이라 구분 불가 — 명백한 설계 실수** (A)
- **군중은 압도적으로 작성자 편이다: 긍정 판정(NTA+NAH) 67.6% vs 부정(YTA+ESH) 32.8%** (354k 글 / 13M 댓글, 2014–2019). "판결받으러 오는 서비스"의 기본 정서는 처벌이 아니라 **면죄**. — De Candia et al., WebSci'22 (A)
- **네이트판은 2026년 현재 "배틀톡"이라는 A/B 투표 게이지 포맷을 이미 운영 중.** 퍼센트+실제 표수 병기, 마감 카운트다운, **댓글마다 작성자의 투표 진영(A/B) 배지**. — m.pann.nate.com/btalk 실측 (A)
- **AITA 파생 앱은 "투표해야 결과가 보인다"를 마케팅 문구로 쓴다** ("Vote & see the results! 👀"). 판정 용어도 완화형(`They're Wrong / You're Wrong`). — App Store (A)
- AITA는 댓글 점수를 숨기지 않는다 → 밴드왜건을 UI가 아니라 **규칙**(1.4/1.5)으로 막으려 함 (사실상 실패)

### 판정 체계
- 5종: `NTA`(당신 아님) / `YTA`(당신 잘못) / `ESH`(둘 다) / `NAH`(아무도 아님) / `INFO`(정보부족)
- 결정: 게시 **18시간 후 최상위 댓글 중 업보트 1위**의 판정이 최종. 비율·득표수 미표시
- 사이드바 카피가 연출 역할: *"The power of the crowd will judge you."*
- **판정별 피드 필터** 제공: Assholes / Not Assholes / Everyone Sucks / No A-holes Here / Updates
- 게이미피케이션: 최다추천 판정 시 flair 포인트 +1 → 15단계 칭호 (`Partassipant(1) → Certified Proctologist(20) → Supreme Court Just-ass(100) → Galasstic Overlord(1500)`)

### 3가지 뷰 공존
1. **랭킹/톡톡 리스트**: `순위 | 썸네일 72px | 제목 1줄 말줄임 + 댓글수(빨강) | 조회·추천(회색)`. **본문 미리보기 0줄.** 유일한 컬러 숫자가 **댓글수**

### 배틀톡 (A/B 투표 포맷)
- 히어로: `HOT 배지` + `86명 참여` → "A vs B" 제목 → **큰 좌우 분할 게이지**(보라 31% / 하늘 69%, 퍼센트를 바 안쪽 끝에 큰 글씨) → 바 아래 선택지 라벨 → ⏱`2일 0시 55분 남음`(빨강) → CTA `참여하기`
- 리스트: `LIVE + N명 참여` → 제목 → `(A) —VS— (B)` 칩 → 얇은 분할 게이지 → `31%` … **"11개의 댓글이 격렬한 토론 중!"**(파란 강조) … `69%`
- 상세: **`31% 27표` / `59표 69%` — 퍼센트와 실제 표수 병기**
- 투표 전에도 결과가 그대로 보임 (스포일러 방지 없음)
- 탭: `진행중 / 지난 / 참여한 배틀`

### 훔칠 만한 것 2개
1. **"이 투표의 핵심은?"** — 게이지 아래 회색 박스. **양측 입장을 각각 한 문장씩 중립 서술 + "여러분은 어떻게 대처하시나요?"로 마감.** 긴 사연을 다 안 읽고도 투표 가능하게 만드는 장치
2. **댓글 작성자 닉네임 앞에 투표 진영 배지**(보라 A / 하늘 B). 섹션 제목도 `👥 티격태격 의견나누기`

## 니편내편 적용 제안 (에이전트 원안 10개)

1. **카드: 제목 3줄, 본문 2~3줄 고정, 판결 pill은 제목 바로 아래 작게.** 레딧 실측값이 검증된 기준선. 네이트판 피드뷰의 8~10줄은 스크롤 효율 나쁨
2. **게이지는 "판결"이 아니라 "지금 몇 대 몇"으로. 퍼센트와 표수 병기.** 배틀톡 `31% 27표 / 59표 69%` 형식. 퍼센트만 쓰면 3:1이 75%로 부풀고, 표수만 쓰면 비율이 안 읽힘
3. **투표 전 결과를 가려라. 단 "가림"이 아니라 "잠금 해제"로 연출.** AITA 앱이 `Vote & see the results! 👀`를 핵심 마케팅 카피로 씀 = 공정성만이 아니라 **전환율 장치**. 구현: 블러 처리된 바 + "투표하면 결과가 열려요" → 투표 시 0%에서 실제값으로 애니메이션
4. **판결 색 4종을 다 다르게.** 레딧은 NTA와 NAH가 같은 색이라 구분 불가 — 이 실수를 반복하지 말 것
5. **판정 용어를 완화형으로.** 시장이 이미 그렇게 함(`They're Wrong / You're Wrong`, 배틀톡은 아예 `A/B`). "니편내편"이라는 이름 자체가 가해자 지목이 아니라 편 가르기 프레임이므로 **작성자를 주어로 하지 않는 표현**이 브랜드와 맞음
6. **작성자 보호는 "결과 완화"가 아니라 "댓글 규칙 + 삭제 유예 + 참여 문턱"으로.** 인신공격/아마추어 진단/주작 의심 금지를 **신고 사유 라디오 버튼**으로 노출 + N시간 삭제 유예 + 원문 스냅샷 + 논란 글 참여 문턱 모드. **결과 표현 완화는 하지 마라** — 데이터상 이미 작성자 편이 67.6%
7. **게시 전 "내가 잘못했을 수도 있는 부분은?" 필수 입력.** 레딧 Judgement Bot의 그것. (a) 일방적 하소연 필터링 (b) 불리한 판결의 충격 완화
8. **논점 요약 카드 ("이 투표의 핵심은?")** — 사연 서비스 최대 이탈 지점이 "본문이 길다"인데 이걸 우회. 반드시 양쪽 대칭 서술
9. **댓글에 투표 진영 배지.** 소수 진영 댓글 따로 노출("반대편은 이렇게 봤어요") 밸런싱 UI로 확장 가능 — 레딧이 구조적으로 못 하는 것
10. **판정별 피드 필터 + 아카이브.** 결론난 사연은 판정 자체가 소비 동기. PublicConsensus의 "백서" 개념까지 확장 가능
