# ST2 — 익명 커뮤니티 익명성 안심 장치 / 실패 사례

## 핵심 발견

- **익명성 안심 UX의 본질은 "문구"가 아니라 "구조의 설명"이다.** 블라인드는 전용 페이지(`/logic`)에서 4단계로 설명: ① 회사 이메일이 왜 필요한지 ② 이메일은 공개되지 않은 복합변수로 암호화 ③ 암호화된 이메일과 계정 정보를 **완벽히 분리된 DB**에 저장 ④ 퇴사자는 `ex-회사명`. "믿어달라"가 아니라 **"구조상 불가능하다"**를 보여준다. — https://kr.teamblind.com/logic (A)
- 블라인드 원칙: **"Verification confirms employment, not identity"** — 고용은 확인하되 신원은 확인하지 않음. 12년간 작성자 신원이 드러난 사례 0건을 신뢰 근거로 제시. — https://www.teamblind.com/blog/how-we-protect-anonymity (A)
- 가입 화면 카피 실물: "Sign Up Securely / Use your work email to get the most out of Blind **while protecting your anonymity**" — https://www.teamblind.com/sign-up (A)
- 에브리타임 익명 ID 규칙: 글 작성자 `익명(글쓴이)`, 댓글은 **단 순서대로** `익명1`, `익명2`. — https://times.postech.ac.kr/news/articleView.html?idxno=23869 (B)
- **에타 안티패턴: 익명이 기본값이 아님.** 매번 '익명' 체크 필요 → 유저가 자동 체크 유저스크립트를 만들어 씀. — https://greasyfork.org/ko/scripts/386305 (C)
- 블라인드조차 신고 누적 자동 블라인드의 취약성을 인지하고 **악의적 신고자 역제재 로직**을 도입. — https://www.teamblind.com/kr/post/블라인드-신고제도-mvMEqdhc (B)
- 익명 앱의 죽음은 **"독성 → 기관 차단 → 이탈"** 3단계. **익명 철회는 회생책이 아니라 사망 가속제** (Yik Yak 핸들 도입 후 이탈 가속). — https://em360tech.com/tech-articles/why-did-yik-yak-fail-how-messaging-app-died (B)
- 정량 근거: 전체 이용자의 **1% 미만이 갈등의 74%를 유발** (조지아텍 연구 인용). — https://times.postech.ac.kr/news/articleView.html?idxno=23869 (B)

## 서비스별 요약

### 블라인드
- 안심 장치: `/logic` 4단계 아키텍처 서사 (다이어그램 없이 텍스트 위주 → 시각화 여지 큼), 위협 시나리오별 반박형 카피, 인증 로직 특허를 신뢰 근거로 제시
- ID: 사용자가 고른 **고정 익명 닉네임 + 회사명 뱃지**. 100명 미만 기업은 '새회사/스타트업'으로 뭉뚱그려 재식별 방지, 퇴사자 `ex-회사명`
- 신고: 자동 글숨김. 판단 기준 공개 — 신고 수, **조회수 대비 신고 수**, 신고 사유, 사유 키워드 존재, 조직적/허위 신고 존재. 조직적 악의 신고는 **신고자를 제재**
- 그림자: 엘리트주의(대기업 vs 스타트업 위계), 계정 매매, 신고 누적 자동정지, 여론 조작 취약
- 소명 절차: 공개 공지에 명시 없음 (확인 필요)

### 에브리타임
- 안심 장치 **사실상 없음**. 오히려 "운영자는 작성자를 파악할 수 있다"는 의혹이 있고, 이를 언급하는 글이 삭제·차단된다는 이용자 보고 → 신뢰 훼손
- ID: 계정 닉네임 + 글쓰기 시 '익명' 체크(기본값 아님)
- 신고: 알고리즘 자동 삭제(관찰상 4~5명으로도). 2022.6 안내에서 "신고 누적" 문구 삭제. 2023 **'이용제한 목록'** 추가로 사유 확인 + 제한적 이의제기 시작. 기준은 여전히 비공개
- 성공 요인: 익명 커뮤니티로 시작하지 않았다 — **시간표 자동생성이라는 실용 도구**로 시작 → 강의평가/학점계산 → 커뮤니티가 그 위에 얹힘. 약 400개 대학 455만 명

### Whisper (2024 소멸)
- 2020년 **9억 건 DB 무방비 노출**. 실명은 없었으나 나이·성별·출신지·닉네임·소속 그룹(성적 지향 다수)·**마지막 게시물 위치 좌표** 노출 → 재식별 + 협박 가능
- 2024.9 Google Play, 10월 App Store에서 공지 없이 제거. 아동 그루밍 수사 반복

### Secret (2015, 출시 16개월 폐업)
- $3,500만 조달, 밸류 $1억. 창업자: 익명성은 "**the ultimate double-edged sword, which must be wielded with great respect and care**"

### Yik Yak (2017 폐업 → 2021 부활 → 2023 Sidechat 인수)
- $7,500만 조달, **매출 사실상 0**. 2015년 살해 협박·인종차별 → **대학들이 캠퍼스 네트워크 차단** → 유저 급감
- 회생책으로 핸들(반익명) 도입 → 익명이 유일한 매력이던 유저층 더 이탈

### Fizz / Sidechat (현행, 모더레이션 참고 모델)
- `.edu` 검증하되 표시는 익명
- **3층 모더레이션**: AI가 위반의 80% 처리 + 중앙 Trust&Safety 팀 + **캠퍼스 학생 모더레이터 8,000명+**(교육·퀴즈 통과 필수). 핵심: **단독 삭제 불가, 모더레이터 투표로 결정**
- 그럼에도 UNC 시스템은 2024년 전 캠퍼스 차단

### 대나무숲 (쇠퇴)
- 중개형 익명(제보자 DM → 운영자 대신 게시), `#1234번째 제보` 일련번호
- 실패: 사실확인 불가 구조 악용한 허위 제보 / 검증 시도 시 익명성 목적과 충돌 / 무보수 운영자 번아웃 / 에타에 흡수

## 니편내편 적용 제안 (에이전트 원안)

1. **FEAT-09 "신고 5회 자동 블라인드"는 A3 그대로 — 반드시 보정**
   - 절대 횟수 대신 **조회수 대비 신고율** 병용 (블라인드 공개 기준)
   - 반복 신고 / 단시간 집중 신고 감지해 가중치 삭감, 신고 1일 한도
   - **악의적 신고자 역제재**
   - 자동 블라인드는 삭제가 아니라 **"가림 + 30일 유예"** — 정보통신망법 제44조의2 임시조치(30일 접근차단 → 이의제기 시 재게시) 관행과 정렬
2. **가려진 글은 "빈칸"이 아니라 "상태 카드"로** — 카드 자리 유지, 투표수/댓글수 유지. 작성자에게만 위반 사유 + AI/사람 판정 여부 + **[이의 제기] 인라인 버튼**. 마이페이지에 **'내 제재 내역'** 탭
3. **소셜 로그인이 최대 신뢰 리스크** — 카카오/애플 로그인은 서비스가 신원 연결고리를 보유한다는 뜻. (a) 소셜 식별자 단방향 해시 + 게시물 테이블 조인키 분리, 또는 (b) 정직하게 "법적 요청 시 특정 가능" 고지. **애매하게 두는 것이 최악(A2)**. 온보딩에 **'익명 로직' 1페이지** (블라인드에 없는 다이어그램을 넣으면 차별점)
4. **익명 ID는 사연 단위로 스코프 제한** — `익명1/익명2`, 작성자 `글쓴이`, 사연 넘어가면 리셋. **닉네임은 마이페이지에서만, 피드 노출 금지**(A12). 번호는 발급 시점 고정 저장(삭제 시 밀리지 않게). 익명은 기본값이자 유일값(A1 차단)
5. **니편내편의 "+α"를 정해야 한다** — 후보는 **AI 시뮬레이션**. 커뮤니티가 조용해도 혼자 쓸 수 있는 유일 기능 = 락인 축. 반대로 투표는 A7 위험 — **최소 투표수 미만이면 % 감추고 "아직 투표가 적어요"** 표시
6. **미성년 유입 대비** — 호주(16세 미만, 2025.12)·프랑스(15세 미만, 2026.1)·스페인·말레이시아(2026.7) 연령 규제 확산. 감정배출+연애 조합은 규제 노출도 높음
